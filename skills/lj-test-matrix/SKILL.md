# LJ 组合测试矩阵（lj-test-matrix）

> 事实源：docs/01-产品设计.md（PRD）§8.2（改价）、§8.7（取消）、§8.8（信用全表）；架构 §4.1-§4.4（守卫/竞态/幂等机制）；docs/modules/<域>/<ID>-*.md 各模块 §7 业务规则（R-xx）与 §10 验收清单。
> 本技能与 PRD/架构/模块文档修订**同 PR 更新**。

## 触发时机

agent 为履约、信用、支付、改价、取消、缺席、成团等规则密集域写测试（或补测试）时自动装载。产线纪律 1（TDD 先行）：每条 R-xx 规则至少 1 个用例——本技能负责把 R-xx 展开成组合用例清单。

## 一、组合测试方法论：R-xx × 并发 × 幂等 三维展开

对模块文档 §7 的每条 R-xx 规则，沿三个维度展开用例，产出矩阵后再动手写测试：

**维度 1 — 规则本体（R-xx）**

- 正例（规则命中时的标准行为）+ 反例（规则不适用时的行为）。
- 边界值：时间边界（30s / 2h / 12h / 24h / 宽限 5min / late 15min）、金额边界（50% 抵扣上限的整/零头、10% 降价分档线）、状态边界（终态前一刻到达的回调）。

**维度 2 — 并发**

- 计数类规则：构造 2×capacity 并发，断言**恰 capacity 成功 + 其余走退款分支**（C3 §10 验收：并发 2×capacity 支付恰 capacity 成功）。
- 竞态类规则：定时判定 vs 人工操作并发（架构 §9：竞态以「先到者生效、后到者幂等无操作」收尾——两个用例分别断言两种到达顺序）。
- 锁类规则：同律师同时间段并发加锁，恰 1 成功（部分唯一索引，架构 §4.2）。

**维度 3 — 幂等**

- 同一支付回调重复到达（Inbox 双唯一）：恰一次推进，第二次无操作。
- 同一 MQ 事件重复投递（at-least-once，按 eventId 幂等）：恰一次生效。
- 同一 job 重复执行（SKIP LOCKED 抢占后执行器幂等回查）：恰一次生效。
- 同一幂等号重复下单/退款请求：返回同一结果或 409，不得重复扣款。

**产出格式**：`用例ID = R-xx | 维度标注 | 前置 | 动作 | 断言`，先列清单（TDD 的测试清单即失败测试清单），逐个 RED→GREEN。

## 二、改价矩阵（PRD §8.2，组合展开）

| 改价方向 | 是否允许 | 对已锁定用户 | 对新发起拼团 | 律师惩罚 |
|---|---|---|---|---|
| 无进行中拼团 | 自由改价 | — | 按新价 | — |
| 有进行中拼团·涨价 | 允许 | 按快照价 | 按新价 | 信用 -5 |
| 有进行中拼团·降价 ≤10% | 需平台审批 | 按快照价 + 平台积分补偿 | 按新价 | 信用 -15 |
| 有进行中拼团·降价 >10% | 需平台审批 | 按快照价 + 积分补偿 + 优惠券 | 按新价 | 信用 -30，暂停接单 3 天 |

- 补偿：对象=所有已支付且未完成服务的用户；**补偿金额 =（原价 - 新价）× 用户已支付金额占比**；形式=平台积分（1 元=100 积分、有效期 180 天、可抵扣不可提现）；发放=降价生效后 24h 内。
- 积分抵扣：100 积分=1 元，**单次抵扣不超过订单金额 50%**（边界用例：恰好 50% 整额 / 50% 带零头 / 50%+1 分）。
- 撤销：24h 内可撤销恢复原价、不扣信用、需通知；超 24h 不可撤销（边界用例：24h 整点前后）。
- 频率：每 30 天最多 3 次（含涨与降），超限走审批；恶意频繁改价 → 信用 -20，严重者暂停接单。
- 记录：所有改价进 PricingHistory。

## 三、取消矩阵（PRD §8.7 + §8.6）

| 角色 | 时间 | 处理 |
|---|---|---|
| 用户 | 开始前 ≥2h | 全额退**或**免费改期一次（组合点：改期 reschedule_used） |
| 用户 | 开始前 <2h | 退 50% **或** 扣信用（两分支都要用例） |
| 用户 | 到点未进 | 按缺席处理（转 §8.5） |
| 律师 | 取消 ≥24h | 可取消，全额退款用户，信用 -10 |
| 律师 | 取消 <24h | 平台审批，全额退款 + 信用 -30 + 场次总价 20% 违约金补偿用户 |
| 律师 | 缺席（宽限期未进场） | 自动终止 + 全额退款 + 信用 -50 + 场次总价 50% 赔付 |
| 平台 | 任意 | 全额退款，**无信用影响** |

- 违约金分配：全额按用户支付金额占比补偿用户，**平台不抽佣**；场次总价基数=单价×律师选定人数 或 律师设定的场次总价（开团时修改的以修改后为准）。
- 连续 2 次取消/缺席 → 暂停接单 7 天。
- 退款原路退回 1-3 个工作日。
- 组合点：改期迁移走「新建行」而非 UPDATE（架构 §4.1）——用例断言旧行状态与回链。

## 四、信用全表（PRD §8.8）

用户：正常参与 +分；提前取消 轻微扣分；2h 内取消 扣分；缺席 重扣；多次缺席 限制发起/参与拼单。
律师：正常履约 +分；取消 ≥24h -10；取消 <24h -30；缺席 -50；拒绝/超时 C2B -5；连续 2 次取消/缺席 暂停接单 7 天；有进行中拼团时涨价 -5；降价 ≤10% -15；降价 >10% -30+暂停接单 3 天；恶意频繁改价 -20、严重者暂停接单。

组合点：信用事件是不可变流水（credit_events），账户快照（credit_accounts）是唯一事实源（架构 §4.7）——同一事件重复投递不得重复扣分（幂等维度必测）；限制类后果（限制拼单、暂停接单）由信用模块发「限制令」，trade 入口校验——跨模块用例走事件消费。

## 五、执行纪律

- 测试运行器：前端/Node 侧默认 `bun test`；NestJS 侧 vitest 或 jest（由脚手架统一后固定，全仓不混用）——docs/modules/README.md 通用验收门。
- 每条 R-xx 至少 1 用例（产线纪律 1）；并发/幂等用例对资金与状态机规则**强制**（C3 §9）。
- 禁止：points 换算用 float；先插 enrollment 后改 joined（顺序反了必超卖，C3 §9）。
- 断言不得为通过而削弱；数据用虚构样例（周女士/张明远等口径见 prototype README）。

## 验收判据（可观察）

- 测试文件可映射回 R-xx 编号（注释标 `// R-04` 等）；评审时逐条核对覆盖。
- 资金/状态机规则的并发用例与幂等用例缺任一 → 审查不通过。
- 测试清单先于实现出现（TDD），完成声明附运行输出（verification-before-completion）。

## 与模块文档的联动

- 模块文档 §7（R-xx）与 §10（验收清单）是输入；本技能把清单展开为三维用例矩阵。
- PRD §8 / 架构 §4 修订 → 同 PR 更新本技能的矩阵表。

## 待澄清

价格体系稳定性指数口径（架构 §10-8）、积分抵扣退款还原细节（C3 §11 / 04§8-1）未定——涉及处只测已定义行为，未定义行为不得自行发明断言。
