# LJ 数据安全编码（lj-data-security）

> 事实源：docs/02-架构设计.md（v2.1）§5.2（存储与合规）、§4.6（Agent 草稿管线/实时脱敏层）、§5.1（核心数据模型加密字段）、§6（数据安全行）。
> 本技能与架构文档修订**同 PR 更新**。密钥管理走 secrets 管理，**密钥/证书禁入代码与 skill**（AGENTS.md 红线）。

## 触发时机

agent 改 identity（实名/注销）、agent-assist（脱敏/草稿/知识库）、存储层（OSS/冷存/导出）代码，或设计任何落库个人信息字段时自动装载。

## 规则清单（逐条可执行，带架构出处）

### 1. 列加密 + HMAC 盲索引（架构 §5.2、§5.1、§6）

- 手机号：`users.phone_enc` 列加密 + `phone_blind_idx` HMAC 盲索引（检索用）——**不得明文落库，也不得用可逆加密直接当索引用**。
- 实名（架构 §5.2 合规 R6，核验凭据双轨）：对接公安 CTID/运营商三要素后**默认仅存核验结果+凭据摘要**（KMS 信封加密+密钥轮换）；`real_name_infos` 的 `name_enc / id_no_enc` 密文仅在已声明目的（纠纷处理）下经审批+双人复核临时解密。
- `lawyer_profiles.license_no_enc`：执业证号纳入列加密。
- 律所授权文件：入加密 OSS 资料库（架构 §5.2 合规 R20）。

### 2. 实时脱敏层接入点（架构 §4.6、§1.3-5）

- **用户原文进 LLM 前必须过实时脱敏层**：与训练管线同源 NER+规则；姓名/证件/电话/地址→占位符后才进 RAG 与 LLM；脱敏占预算 ≤1s（8s P95 总预算的一部分）。
- 律师端气泡显示占位符，由律师自然表达。
- 敏感话术硬拦（承诺结果/包赢类）不生成草稿。
- 接入点在「房间用户消息（MQ）→ 脱敏 → 意图识别 → RAG → LLM」管线的**最前端**——任何跳过脱敏层直达 RAG/LLM 的旁路即 BLOCKER。

### 3. 分级导出（架构 §5.2 合规 R10）

- 本人消息全量；他人消息默认去标识（昵称/ID 掩码、正文保留以维持证据上下文，导出包附告知）。
- **实名信息与录音不在默认导出范围**（录音走本人单独申请）。
- 导出请求入审计；异步加密包 + 限时下载链接。

### 4. 到期处置作业（架构 §5.2）

- OSS 生命周期规则到期自动删除或匿名化转统计；删除动作入审计。
- 消息冷存：热存 PG 90 天 → OSS，留存自交易完成之日起 ≥3 年（见 lj-compliance-guards 红线 2）。
- 账号注销删除范围矩阵（架构 §6 账号注销行）：实名与授权记录删除或不可逆匿名化；消息与录音按法定留存至 3 年后自动删除；交易记录按税务/电商法要求匿名化留存必要字段。

### 5. 数据分类分级（架构 §5.2 合规 R19）

- **L4 敏感**（实名/支付/咨询内容/录音）：差异化管控——加密、审批、审计。
- **L3 行为数据**；**L2 公开配置**。
- 新增字段时先定级：L4 字段未走加密+审批+审计三件套 → BLOCKER。

### 6. 其他编码规则（架构 §6 数据安全行）

- 传输 TLS；日志敏感字段入库前脱敏（ELK/OpenSearch，架构 §7.2）。
- 后台查看实名需审批+审计；最小化采集。
- 评价匿名：`reviews` 不含 from，`review_credentials` 凭证分离存储，运营默认不可 join，纠纷调查经审批（架构 §5.1、§6）。

## 验收判据（可观察）

- 新增个人信息字段无定级/无加密方案 → 表结构审查不通过。
- LLM 调用链路存在跳过脱敏层的路径 → BLOCKER。
- 明文手机号/证件号出现在任何表列、日志或导出默认包 → BLOCKER。
- 删除/匿名化操作无审计记录 → 不通过。
