## 1. 拆分原则

1. **边界对齐架构模块**：功能模块不跨架构模块边界（架构 §3.2 的 13 模块 + §3.3 三服务），一个功能模块只写一个架构 schema；
2. **单一职责、可独立交付**：每个模块可独立开发、测试、验收（配合技能指南 §9.2 分阶段装载）；
3. **接口先行**：模块间只通过"接口 + 领域事件"协作（架构 §2.1 Outbox），上下游必须列全；
4. **规则可溯源**：每条业务规则标注 PRD/架构出处，验收判据可测试；
5. **横切机制显式建模**：时间段锁、调度、通知、风控是机制服务，不是某个模块的私有功能。

## 4. 模块细节（索引）

每模块的**详细技术文档**（DDL、接口契约、事件载荷、规则算法、AI 开发标准、验收清单）位于 `docs/modules/<域>/<ID>-<名称>.md`。本节仅保留一页式摘要（职责/关键依赖/规则锚点）：

### A 身份与账号

- **A1 注册登录与双角色**（identity）：手机号验证码登录、JWT 双 token、角色切换重签 claims、界面数据隔离；**注册环节年龄声明**（架构 §6 未成年人保护）。依赖 → I1。锚点：PRD §7.1.1/§3；架构 §6。
- **A2 实名认证与同意管理**（identity）：实名闸口（姓名+身份证，核验通道 ⚠）+ **consents 全 scope 管理（realname/training/recording）**——支付流程内训练数据独立授权页（可拒绝不影响拼单，仅该房间消息不进语料）、设置中心撤回入口；实名核验凭据双轨（默认仅存摘要+凭据，受控解密审批+双人复核）。撤回删除执行链：A2 发起 → **D5/I3 按 source_msg_id 反查物理删除**。事件：TrainingConsentGranted/Revoked、TrainingDataPurged、RealNameVerified。锚点：PRD §7.1.1；架构 §4.4 闸口、§5.2 合规 R3/R6。
- **A3a 律师资质审核**（identity schema）：执业证/律所授权提交、人工审核（3 工作日 SLA）、补充重提、停用/恢复；license_no 列加密；律所授权文件入加密 OSS。锚点：PRD §7.2.1；架构 §5.1/§5.2。
- **A3b 律所进件**（支付网关 schema，**firm_merchants 状态机归支付网关持有，identity 只读**）：提交→机构审核→生效→变更→停用；生效才可下发分账；对公账户变更触发重新进件+变更期暂停分账（事件 FirmMerchantSuspended→F3 暂停）；保证金专户冻结 ⚠；年度复验（事件 FirmMerchantReverifiedDue→I2 job）。锚点：架构 §3.3-3、§4.4/§4.5。
- **A4 账号注销**（identity）：申请→冷静期 ⚠15 日→资产清算（进行中场次/待结算/积分）→删除；删除范围矩阵（实名与授权记录删除/匿名化；消息录音留至法定 3 年；交易记录匿名化留存）。锚点：架构 §4.1/§5.2。

### B 律师配置

- **B1 时间表管理**（schedule）：按周重复模板 + 单场时长（60/90/120）；状态视图（空闲/已占用/已锁定）；模板变更不影响已排期。锚点：PRD §6.1/§7.2.2；架构 §4.2（模板物化）。
- **B2 时间段占用锁**（schedule，机制服务）：部分唯一索引（(lawyer_id, slot_start)，活跃三态）；同事务加锁/释放；PENDING_PAYMENT+10min TTL；每用户对同律师 ≤1、全局 ≤3；reaper job。锚点：PRD §6.5；架构 §4.2。
- **B3 默认价格与1对1价格配置**（pricing）：默认人头价/场次总价/开团人数/接受范围/沟通形式/1对1价格矩阵（区间校验：文字 50-300/次、语音视频 100-500/15min）；修改产生新 PriceVersion + 通知已参与用户。锚点：PRD §6.1/§7.2.3/§9.3；架构 §4.3。

### C 交易

- **C1 B2C 开团（含律师场次看板）**（trade）：选段→开团配置（默认值可改本次）→同事务加锁→报名中；enroll_deadline（默认开始前 24h ⚠）。**律师侧场次数据看板接口**：`GET /lawyer/sessions/stats`（报名率/成团率/到场率/1对1转化率，读 H4 聚合或读副本）。锚点：PRD §6.2/§7.2.4/§7.2.6；架构 §4.1。
- **C2 C2B 发起拼团**（trade）：选段（PENDING_PAYMENT 锁）→子范围（默认范围内）→分摊额（默认总价÷子范围最低人数）→**结构化问题标签引导（消费 E3 的 GET /specialty/question-tree，内置引导 UI，非 E1 管线）**→截止（默认 24h）→发布锁快照；**一键重新发起**（复制原任务参数）。锚点：PRD §6.3/§7.1.3/§9.2；架构 §4.1/§4.2。
- **C3 报名与支付成团**（trade+payment）：浏览（仅过审律师）→按快照价支付（实名闸口）→原子守卫成团锁人→截止竞态兜底（30s 停新单/终态自动退款）；积分抵扣 ≤50%（依赖 F4①切片）。**验收拆两期：①现金支付+守卫；②积分抵扣用例**。锚点：PRD §7.1.2/§7.1.4/§8.1；架构 §4.4。
- **C4 C2B 律师响应与双向转化**（trade）：12h 确认/拒绝（超时自动拒+信用 -5）；确认生成履约 Session；认领转化（快照价迁移、新建行、24h 退款窗）。锚点：PRD §6.4/§7.2.5；架构 §4.1。
- **C5 改期**（trade+fulfillment）：≥2h 申请（免费一次）→律师 12h 确认 ⚠模式待定→同事务（旧报名免违约金取消+新段锁+新建行+快照沿用）。锚点：PRD §8.3/§8.7；架构 §4.1。
- **C6 改价与补偿**（pricing+benefits）：规则引擎（三档分级：涨价 -5 / 降价≤10% 审批+积分补偿 -15 / 降价>10% 审批+积分+券 -30+停接 3 天）；30 天 3 次窗口；24h 撤销（不扣信用）；补偿 =（原-新）× 支付占比，24h 内发放。**①期审批未就绪时走 H3 人工兜底工单**。锚点：PRD §8.2；架构 §4.3。

### D 履约

- **D1 房间生命周期**（fulfillment+RTC/IM）：准点开房 job；宽限 5min **锚定约定开始时刻**；开房失败→平台取消分支（全额退款不扣律师信用）；房间形式按律师设置。锚点：PRD §8.4；架构 §4.5/§4.9。
- **D2 提醒服务**（notify+调度）：24h/1h/10min/1min 四档（job 事实源+延迟消息优化）+ 房间内 Agent 同步提醒；确认到场/申请改期入口。锚点：PRD §8.3；架构 §4.5。
- **D3 到场与缺席判定**（fulfillment+RTC/IM）：presence 事件幂等写；宽限结束时点快照判定（30-60s 抖动容忍）；normal/late(≤15min 旁听)/absent(>15min)；律师缺席前置校验开房 job。**用户缺席费用：70% 律师 + 30% 平台积分按到场用户支付金额占比分配**。锚点：PRD §8.4/§8.5；架构 §4.9/§4.4。
- **D4 取消与违约处理**（fulfillment+payment+credit）：取消规则全表（用户 ≥2h 全退/改期、<2h 退 50% 或扣信用；律师 ≥24h -10 全退、<24h 审批+-30+20% 违约金；平台任意全退）；律师缺席 50% 赔付；连续 2 次停接 7 天；违约金扣减顺序（待结算→保证金专户）。锚点：PRD §8.6/§8.7；架构 §4.1/§4.4。
- **D5 会话与消息**（RTC/IM+fulfillment）：conversations 三型；同步风控前置→广播→MQ 落库；per-room seq 断线补拉+迟到回填；@Agent/@律师差异化；**房间须知内容块展示接口**（配置在 H7，进房时拉取）；录制前置（双方 consent 信令才启动云录制；拼单房间默认不录制）；**训练语料 source_msg_id 标记与撤回删除执行**（受 A2 撤回事件驱动）。事件：OneOnOneConversationCreated、TrainingDataPurged（执行方）。锚点：PRD §7.1.5/§7.2.8/§11.1；架构 §4.8/§5.2。

## 5. 端到端流程串联（模块协作链）
