# ADR-0002 M0 基建裁决（迁移工具 / CI 平台 / lint）

> 状态：迁移工具**用户已拍板确认**（Flyway，2026-10-13）；CI 平台与 lint 为默认裁决（⚠ A4 假设执行，**用户可翻转**；翻转时新增 ADR 覆盖本决策）
> 关联：架构 §5.2（迁移/备份候选基线）；开发计划 §4.1 M0-1/M0-3/M0-5；ADR-0001（收口其遗留的迁移工具子项）
> 效力：关闭 M0-1「技术栈定版」最后一项遗留（数据库迁移工具）；确认 M0-5 的 CI 平台与 lint 工具链；默认 Flyway 未偏离架构 §5.2 候选，**无需架构脚注回写**（docs#F11 闭环零成本）

## 决策

| 项 | 定版 |
|---|---|
| 数据库迁移工具 | **用户拍板（2026-10-13）**：**Flyway 社区版**（开源，Apache 2.0），以官方 Docker 镜像 `flyway/flyway` 独立运行（锁 tag），不进 Node 依赖树；迁移文件一律 `.sql`（SQL-first 口径不变） |
| down 演练口径 | Flyway 社区版无 undo → M0-3「迁移 up/down 幂等演练」释义为：**drop 业务 schema 后整库重放**（replay 至最新），**非逐版本 undo 回退**（此为口径差异，特此明写） |
| CI 平台 | ⚠ **默认裁决（可翻转）**：**GitHub Actions**（仓库托管 github.com，M0-5 原「azure-devops 备选」撤销） |
| lint / 格式化 | ⚠ **默认裁决（可翻转）**：**ESLint 9 flat config + Prettier**（规则细节由 M0-2 脚手架裁量固定） |

## 候选对比（调研摘要）

| 维度 | Flyway | Liquibase | node-pg-migrate |
|---|---|---|---|
| up/down 验收口径可达性 | 社区版**无 undo**：undo 自 v9.8.0 起移入 `flyway-proprietary` 模块，「running the undo migrations still requires a Teams or Enterprise license」（官方发布说明原文）→ down 演练只能整库重建重放 | 社区版 rollback 命令可用；formatted SQL 需**手写 `--rollback`** 段（自动回滚仅限 XML/YAML/JSON change 类型；存储过程等自动回滚为 Pro 功能） | **原生 down**：`migrate down [N]` / `redo`；基于操作栈可部分自动推导 down（官方自述「sometimes」） |
| 与 NestJS/Node 产线集成 | JVM 工具：官方 Docker 镜像独立跑，与 NestJS 进程物理解耦，不引 JVM 进依赖树 | 同为 JVM：官方 Docker 镜像 `liquibase/liquibase` 独立跑 | 纯 TS/Node：与 NestJS 同工具链（Node 22+、PG 14+），可直接进 devDependencies |
| SQL-first 契合度（本项目口径=迁移一律写 .sql，不用 DSL/XML） | **最纯**：纯 `.sql` 文件、无专有格式 | formatted SQL 需 `--liquibase formatted sql` 文件头 + `--changeset` / `--rollback` 指令——文件内嵌工具注解，非 verbatim SQL | TS 优先工具（`.sql` 文件可用但可编程迁移才是其长处），纯 SQL 口径下优势用不上 |
| CI 集成成本（GitHub Actions） | `docker run flyway/flyway` + PG service 容器，一步到位 | 同左（`docker run liquibase/liquibase`） | Node 步骤内直接跑 CLI，最轻 |
| 维护活跃度 / 许可风险 | 活跃（v13.7.0，2026-09；Docker 镜像随版更新）；社区版开源但有商业化收缩先例（v10 起数据库支持模块化拆分、undo 收入商业模块） | 活跃；社区版 Apache 2.0 | 活跃；MIT；单一 PG 焦点、维护者多名 |
| 架构 §5.2 候选符合性 | **在候选内** | **在候选内** | **偏离候选**（§5.2 未列；选用须按 docs#F11 回写架构脚注） |

## 理由

- **Flyway**：① 在架构 §5.2 候选（Flyway/Liquibase）内，零回写成本；② SQL-first 最纯粹，社区版即「无专有格式的纯 SQL 迁移」；③ Docker 镜像运行使迁移成为部署管线中独立于应用进程的阶段（与「调度以 DB 为事实源」的部署观一致），JVM 不污染 Node 产线；④ down 口径差异可控——「drop schema 后整库重放」比逐版本 undo 更严格地验证「从零重放到最新」的确定性与幂等性，恰是 M0-3「幂等演练」的本意。
- **GitHub Actions**：仓库即托管 GitHub，PR 状态/必过检查原生集成；撤销 azure-devops 备选可减少 M0-5 双轨维护。
- **ESLint 9 flat + Prettier**：flat config 自 v9 起为默认配置体系（eslintrc 官方弃用）；ESLint 管静态质量、Prettier 管格式，分工清晰；flat config 在 monorepo 下原生支持多包共享配置。

## 影响与回写

- **dev 运行形态降级脚注（M0-3 施工，2026-10-13）**：施工机无容器运行时（无 Docker/Podman/WSL 发行版，且不可安装需管理员权限的软件）→ M0-3 按双轨交付：docker 轨交付 `docker/dev/docker-compose.yml`（供 M0-5/T4 的 GitHub Actions 容器与未来 docker 环境；compose 运行验证留待 T4）；portable 轨在本机以免安装 zip 实际演练（PostgreSQL 15 EDB binaries + Flyway CLI + Temurin 17 JRE，解压于仓库 `.tools/`，不入库，口令占位+env 注入）。**工具身份不变（Flyway 社区版 + PostgreSQL 15），不改变本 ADR 任何决策面**；portable 栈暂不含 pgvector（M0 无向量操作；compose 镜像口径已含 pgvector，E3 施工前补齐 portable 侧）。
- 开发计划 §4.1：M0-1 迁移工具子项关闭（标注默认裁决、用户可翻转）；M0-3 产出栏指向本 ADR；版本 v1.2→v1.3（修订记录见该文档文首）。
- 架构 §5.2：默认 Flyway 未偏离候选基线，无需脚注回写。
- M0-3 施工约束：锁定 Docker 镜像 tag（禁 latest）；迁移目录只含 `.sql`；`flyway clean` 仅限 dev 演练（保持 Flyway 默认 prod 禁用 clean 不动）；演练报告须明示「down=整库重建重放」口径。
- M0-5 施工约束：CI 迁移检查 = PR 触发 `flyway validate` + 迁移演练 job（GHA service 容器起 PG15 → migrate → drop 业务 schema → migrate 重放）。

## 风险与翻转代价

- ~~⚠ 三项均为默认裁决（A4 假设执行）~~ → 迁移工具已用户拍板（2026-10-13 确认 Flyway，翻转窗口关闭）；CI 平台与 lint 仍为默认裁决，用户翻转时新增 ADR 覆盖即可；翻转窗口最好在 M0-5 开工前。
- Flyway 社区版功能边界漂移风险（Redgate 商业化先例：undo 专有化、v10 数据库支持模块化）→ 缓解：锁 tag、版本升级走 ADR。PG 支持仍在社区版内：v10 起 Maven/API 用户需显式加 `flyway-database-postgresql` 依赖，官方 Docker 镜像已捆绑，本项目走 Docker 路线不受影响。
- down 演练为「整库重建重放」口径，**不是**逐版本回退：生产回退实际依赖前向修复（新增补偿迁移）+ PITR 备份（架构 §5.2 日全量+WAL）——与业界主流实践一致，但须在 M0-3 演练报告与运维手册中明示。
- 翻转代价：迁移文件均为 `.sql`，早期（迁移数 <20）翻转到 Liquibase（加文件头与指令）/ node-pg-migrate（补 down 脚本）的成本≈目录重排+回退脚本补写，随迁移数量线性增长；CI / lint 翻转成本低（M0-5 未开工）。
