## 1. 架构目标与约束

### 1.1 业务目标映射

| PRD 目标 | 架构支撑点 |
|---|---|
| V1 验证"用户愿意低价购买律师时间" | 交易主链路（开团/拼团/支付/成团/履约/结算）高可用、强一致 |
| AI 增强律师效率 | Agent 草稿气泡低延迟、可审查、可度量（AgentReviewLog） |
| 拼单降低门槛 | B2C 开团 + C2B 拼团双交易模型，价格快照保障信任 |
| 合规经营 | 资金不过平台账户（持牌机构分账）、实名、留存、风控、脱敏 |

### 1.2 非功能需求

| 类别 | 目标 | 依据 |
|---|---|---|
| 可用性 | 交易核心 99.9%（≈月停机 43.8min）；房间服务 99.9%；最低部署形态见 §7.1 | 到点开房属硬实时约束，错过即违约 |
| 一致性 | 资金、成团、时间段锁强一致；通知、看板最终一致 | 金额与锁冲突直接影响资损与履约 |
| 延迟 | 房间内 IM ≤300ms P95；Agent 草稿生成 ≤8s P95（预算拆分见 §4.6） | 草稿气泡是律师工作台核心体验 |
| 规模 | V1 单城市（北京），日活千级、并发房间百级；架构预留 V2/V3 水平扩展 | PRD §11.3 |
| 安全合规 | PIPL/个保法、数据安全法、电商法平台责任；实名信息加密；**聊天/交易类记录留存自交易完成之日起不少于 3 年**（电商法 §31 锚定，较 PRD 的 2 年上调，见 §10-2） | PRD §10.3、§11.2、§14.2 |
| 可观测 | 核心指标（成团率、到场率、1对1转化率、草稿采用率）可实时看板；资损类不变量分钟级巡检告警（§7.2） | PRD §12 |

### 1.3 关键约束

1. **资金合规**：所有资金走持牌支付机构分账（微信电商收付通 / 支付宝直联分账；**先行实现拍板=汇付斗拱延时分账（2026-10-18，04 §8 #41），同属持牌机构分账，通道抽象保留收付通/直付通迁移位**），平台不碰资金、不做资金中转、不自收任何形式的保证金（PRD §9.5、§14.2）。涉及平台侧"收钱"的设计（保证金、缺席分成）一律落在支付机构侧托管账户，平台仅持指令权与台账。
2. **律师费入律所对公账户**：结算对象是律所而非律师个人；分账前置条件是律所在持牌机构完成进件（§3.3-3、§4.4）。
3. **到点硬实时**：宽限期 5 分钟、缺席判定、律师缺席自动终止——调度以 DB 到期任务表为事实源（§4.5），宽限期与缺席判定一律锚定**约定开始时刻**而非实际开房时刻，开房任务延迟 >30s 即电话告警。
4. **AI 不出庭**：Agent 输出永不直接进入房间公屏，必须经律师审查（PRD §7.2.7、§11.1）——草稿管线与消息发送链路物理隔离（§4.6）。
5. **LLM 供应商硬约束**：境内运营、数据不出境、API 输入不留存且不用于供应商训练；采购前签署 DPA/委托处理协议；供应商列入准入合规审查清单，切换供应商需重过合规检查（含出境评估触发条件）。用户原文进 LLM 前必须经过实时脱敏层（§4.6）。
6. **V1 范围**：仅劳动仲裁专项；AI 问题入口、深度服务转化为 V2。架构预留扩展点，不提前实现。
7. **运营前置约束**：等保定级备案、ICP 许可与交易平台相关增值电信许可（证照组合待法务核实）、App 备案——未完成不进 prod（§7.1 门禁）。

## 2. 总体架构

### 2.1 架构风格决策

**决策：模块化单体（Modular Monolith）+ 三个独立部署的专项服务（实时通信、AI Agent、支付网关适配），DB 共享逻辑库但按域分 schema。**

理由：
- V1 团队规模小、域模型仍在快速演化（PRD 内定价规则已多次修订），微服务拆分的分布式复杂度（分布式事务、服务治理）会拖慢迭代。
- 交易主链路（开团→支付→成团→履约→结算）模块间大量强一致操作，单库事务 + **事务性发件箱（Outbox）**是最小正确解。
- 实时通信（IM/RTC 信令）、AI Agent（LLM 调用、向量检索）、支付网关（加解密、证书、回调）三者有独立的伸缩模型、发布节奏与技术栈，独立部署。

**边界强制（v2.0 新增）**：共享库下"禁止跨模块直连他域表"不能只靠纪律——
- 每模块独立 DB role + schema 级权限（只授本模块表）；
- 报表/看板一律走只读副本，副本上放开跨 schema join；
- CI 增加跨 schema 引用静态检查。
V2 剥离微服务时按既有 schema 边界兑现。

**事务性事件机制（v2.0 补全）**：
- Outbox：领域事件与业务状态在同一 DB 事务写入 `outbox` 表，relay 进程投递 MQ（at-least-once），消费者按事件 ID 幂等；投递失败进死信工单。
- Inbox（支付回调专用）：渠道流水号 + 业务幂等号双唯一约束，消费幂等、乱序容忍（非法状态迁移被守卫拒绝并告警）、死信入工单（§4.4）。

**演进路径**：V2 起按"交易服务 / 履约服务 / 信用服务"顺序，从单体中沿既有模块边界剥离为微服务（模块即服务候选，见 §3.2）。

## 3. 领域划分与服务设计

### 3.1 领域地图（DDD 视角）

```
[支撑域] 通知 | 权益(积分/优惠券/备付台账) | 文件/导出 | 风控(敏感词)
[通用域] 身份与认证(含注销) | 运营审核(含进件/规则中心/PIA) | 数据看板
[核心域] 交易(开团/拼团/改期) | 定价与快照(含规则版本化) | 排期与时间段锁
         履约(房间/到场/缺席/取消/改期/1对1) | 支付与结算 | 信用 | AI 辅助
```

### 3.2 模块（未来微服务候选）职责

|---|---|---|
| identity | 注册登录、双角色切换、实名认证（核验凭据双轨，§5.2）、实名单独同意、律师资质审核流、**账号注销状态机** | User、Role、RealNameInfo、Consent、AccountDeletion、LawyerQualification |
| schedule | 律师时间表（按周重复模板）、单场时长、时间段占用锁（具体时刻物化） | TimeSlotTemplate、SlotLock |

| trade | B2C 开团、C2B 拼团、报名、成团/流标状态机、价格快照、**改期**、C2B→B2C 转化 | Session、GroupBuy、Enrollment、PriceSnapshot |

**边界纪律**：模块间只允许通过应用服务接口与领域事件（Outbox）通信，禁止跨模块直连他域表；强制手段见 §2.1。

### 3.3 独立服务

**1) RTC/IM 服务**
- WebSocket 长连接网关 + 房间信令；对接 RTC 厂商 SDK/REST（创建房间、云端录制、回调）。
- **会话模型统一**：房间（room）、私聊、1对1 会话均为 `conversation`（§4.8）；所有文本消息同一条风控链路（§6）。
- **读路径（v2.0 补全）**：每会话单调 `seq`（Redis INCR 发号）；客户端持 seq 断线增量拉取；迟到用户进房自动回填最近 N 条；房间成员关系落 Redis + DB，网关节点故障客户端重连任意节点并按 seq 补消息，房间态可重建。
- **风控位置**：消息发送路径**同步**过敏感词/违规话术双判后再广播；MQ 落库仅做持久化、审计与二次模型复核（命中补拦截 + 工单）。
- **录制前置条件**：1对1 会话须收到双方 recording_consent 信令才启动云端录制（未确认仅不开录制）；拼单房间语音/视频默认不录制（边界声明，未来录制须每人单独同意+须知披露）。
- **presence 权威链路**：join/leave 以 at-least-once MQ 事件（带房间时刻戳）上报 Core，幂等写 attendances；判定以宽限结束时点在场快照为准，30–60s 抖动容忍（§4.9）。

**2) AI Agent 服务**
- 管线：房间用户消息（MQ）→ **实时脱敏层（NER+规则，姓名/证件/电话/地址→占位符，纳入 8s 预算）** → 专项意图识别/问题聚类 → RAG 检索 → LLM 生成草稿（带"AI 辅助，仅供参考"标记）→ 长连接推送律师端气泡 → 律师动作（发送/修改/丢弃）→ AgentReviewLog 落库。
- **@Agent 与 @律师 差异化**：@Agent 消息进草稿管线并生成非法律意见类自动响应（流程指引、信息收集、暖场），法律实质内容一律由律师名义发送；@律师 消息进律师端待办并高亮。
- **V1 辅助能力**：快捷回复库（按律师+专项）、待办提示（drafts.answered 状态 + 未回应问题列表）、1对1建议清单（草稿管线旁路识别深度需求意图，V1.1 排期）。
- **降级显式态**：LLM 故障时律师端明确显示"AI 辅助不可用"，不阻塞律师手打回复。
- **隔离铁律**：草稿写路径与房间消息发送路径无共享写入点；发送动作=把草稿内容作为律师消息提交，经正常消息风控后入房间。

**3) 支付网关服务**
- **最薄协议适配**：验签、证书、报文转换；回调原文验签后投递 Core 支付模块 Inbox 统一推进状态机（网关不拥有业务状态）。
- 封装微信/支付宝分账 API：下单、冻结、续冻、解冻分账、退款、部分退款、对账文件拉取；**保证金/待结算账户指令接口**（§4.4）。
- **进件子域**：律所在持牌机构的进件/二级商户状态机（提交→机构审核→生效→变更→停用）；分账指令仅在进件生效后可下发；对公账户变更触发重新进件+变更期暂停分账（§4.4、§4.5 年度复验）。
- 回调幂等（Inbox 双唯一约束）、对账 T+1 差异工单（SLA：24h 内处置）。

## 4. 核心机制设计

### 4.1 交易与履约状态机

**B2C 场次（Session）**

```
CREATED(报名中) → FULL(满员成团，锁人) → CONFIRMED
→ OPEN(到点开房) → IN_SERVICE(宽限结束) → FINISHED → HOLD(结算冻结期24h/纠纷挂起) → SETTLED
CREATED → FAILED(成团截止未满) → REFUNDED
任意 → CANCELLED(律师/平台取消) → REFUNDED(+违约金流程)
```

- B2C 场次创建时写 `enroll_deadline`（默认开始前 24h，律师开团时可改；规则待产品确认，见 §10-3）。
- 截止前 30s 停止新建支付单；回调到达时场次已终态（FAILED/FULL/EXPIRED）→ 触发"已支付→自动退款→通知"兜底分支，写入 state_transition_log。

**C2B 拼团**

```
PUBLISHED(拼团中，价格快照锁定) → REACHED(达子范围最低人数，锁人)
→ PENDING_LAWYER(待律师确认，12h) → CONFIRMED → 生成履约 Session(进入 B2C 履约流程)
PUBLISHED → EXPIRED(截止未成) → REFUNDED
PENDING_LAWYER → REJECTED(拒绝/超时) → REFUNDED(+律师信用-5)
```

- C2B CONFIRMED 时**生成履约 Session 并新建 enrollment 行**（指向新 Session，回链原 enrollment 与 payment_order），原行置 CONVERTED_OUT——**禁止 UPDATE 迁移报名**，保住支付↔报名审计链；rooms.session_id 统一指向履约 Session。

**C2B→B2C 转化（PRD §6.4）**：律师认领 C2B 任务 → 原 GroupBuy 置 CONVERTED；参与者按快照价**新建 enrollment 行**迁移进新 Session（同 §上规则）；新加入用户按 B2C 定价；通知已参与用户，24h 内可申请退款。

**改期（v2.0 新增，PRD §8.3/§8.7）**

```
改期申请(开始前≥2h) → 律师确认(12h，复用确认模式；超时=改期失败回退)
→ 同一事务: 旧报名取消(免违约金路径) + 新时间段加锁 + 新建 enrollment 行
   (reschedule_used=true，限免费1次) + 价格快照沿用
→ notify 重发提醒、schedule_jobs 重投
```

改期为"用户申请-律师确认"模式（自助改期为备选，复杂度差异见 §10-5）。

**1对1 订单（v2.0 新增状态机，PRD §9.3）**

```
PAID(预付全额) → ACCEPTED(律师接单) → IN_SERVICE → FINISHED → SETTLING → SETTLED
PAID → LAWYER_TIMEOUT(接单后 N 分钟未响应) → REFUNDED(自动全额)
服务开始前 → 全额退；开始后未满单位 → 按比例退(未满15min按50%)
```

- 计量：`consumed_units`（文字=实服务轮次数；语音/视频=RTC 回调实际时长÷15min 向上取整）；`实结 = 单价 × consumed_units`。
- **多退少补（保留 PRD 规则）**：实结 < 预付 → 部分退款指令；实结 > 预付 → 生成补差支付单，**须用户 App 内确认支付（不无密扣款）**，15min 未付按已服务比例结算 + 信用记录。
- 实结确认：服务结束双方确认，超时（默认 30min，待产品确认）按计量数据自动实结。
- 1对1 支付前校验实名闸口；价格配置校验区间（文字 50-300/次、语音视频 100-500/15min）。

**账号注销（v2.0 新增，PIPL §47/§50）**：申请 → 冷静期（建议 15 日，待产品确认）→ 资产清算（进行中场次/待结算/未到期积分处理）→ 执行删除。删除范围矩阵见 §5.2。

**无人到场分支（PRD §8.4）**：宽限期结束全员缺席（含律师）→ 房间自动关闭 → 全员自动退款（走平台取消路径，无信用影响，§4.9）。

所有状态迁移经守卫与 `state_transition_log` 落库，供审计、对账与指标计算。

### 4.2 时间段占用锁（强一致）

- **时间语义（v2.0 明确）**：`time_slots` 仅是按周重复模板（weekday+start）；被选择时物化为具体场次的**绝对时刻（timestamptz）**写入 `slot_locks.slot_start`。全局时区 Asia/Shanghai 单时区。部分唯一索引锁的是具体那一场，不是模板。
- 数据层：`slot_locks(lawyer_id, slot_start, status)`，`(lawyer_id, slot_start)` 上部分唯一索引覆盖 `status IN ('PENDING_PAYMENT','LOCKED','OCCUPIED')`，同一律师同一时间段物理上不可双写。
- 状态语义：`PENDING_PAYMENT`（发起中，待支付）→ `LOCKED`（已锁定待履约）→ `OCCUPIED`（履约中）→ 释放；对应 PRD 三态"空闲/已占用/已锁定"。
- 应用层：B2C 创建 / C2B 发布时在**同一事务**内插入 slot_lock + session/groupbuy。
- **释放（v2.0 修正）**：锁状态迁移与业务状态迁移（流标/拒绝/超时/取消）在**同一 DB 事务**内同步 UPDATE；领域事件只用于通知下游。新增 reaper job：扫描"活跃锁 + 关联实体已终态"超阈值即释放并告警。
- **锁滥用防护（v2.0 新增）**：C2B 发布即锁，但锁同时绑定支付单——支付未完成为 PENDING_PAYMENT 并纳入唯一索引 + 10min TTL 自动释放；每用户对同一律师进行中锁 ≤1、全局 ≤3。
- Redis 锁仅作性能前置，**DB 唯一约束是唯一事实源**。

### 4.3 价格快照与改价引擎

- **快照**：支付下单时把 `unit_price / share_price / price_version` 固化进 Enrollment 的 `PriceSnapshot`；改价仅产生新 `PriceVersion`，不回写快照。**金额字段物化为 NUMERIC 列（严禁 float），外键关联 price_version，JSONB 只存完整原文快照**；`group_buys.snapshot` 为展示冗余，事实源是 enrollments 行。
- **改价规则引擎**（规则表驱动）：
  - 前置检查：是否有进行中拼团 → 涨价（信用-5）/ 降价≤10%（审批+积分补偿，信用-15）/ 降价>10%（审批+积分+券，信用-30+停接3天）；
  - 频率：30 天 3 次窗口计数（Redis sliding window + DB 复核），超限走审批流；
  - 撤销：24h 内撤销恢复上一版本，不产生信用事件，发通知；
  - 补偿计算：`补偿 = (原价-新价) × 用户已支付金额占比`，24h 内发积分（benefits 模块）+ 优惠券（降价>10% 档），全程写 PricingHistory 与补偿流水；
- **规则版本化通用机制（v2.0 新增）**：`rule_definitions(rule_key, version, content, effective_at, publish_status)` 覆盖改价/信用/取消缺席/敏感词/免责话术全部规则；行为发生时快照适用版本（与价格快照同哲学）；变更状态机：草案 → 公示 ≥7 日（重大规则公开征求意见）→ 生效；App 内"规则中心"信息页展示现行版本。
- 通知话术按 PRD §8.2 三档模板渲染。
- **优惠券（v2.0 最小化设计）**：`coupons / coupon_grants`（固定面额、有效期、适用专项），仅支持"降价补偿发放 + 下单抵扣"一个场景，不做运营活动券。
- 平台服务费同机制版本化：`fee_versions`（前期 0% → 逐步 5-10%），settlements 引用生效版本。

### 4.4 支付与分账（合规资金流）

**回调一致性契约（v2.0 补全）**：支付回调 → 网关验签 → 投递 Core 支付模块 **Inbox 表**（渠道流水号+业务幂等号双唯一）→ 统一推进状态机：消费幂等、乱序容忍（非法迁移被守卫拒绝并告警）、死信入工单。

**成团原子守卫**：多个支付成功回调并发到达时：

```sql
UPDATE sessions SET joined = joined + 1
WHERE id = ? AND status = 'CREATED' AND joined < capacity
RETURNING joined;
```

更新失败（满员/终态）→ 触发自动退款分支。

**分账触发状态机（v2.0 补全，合规 R1）**：

```
用户支付 → 冻结(持牌机构托管) → 成团: 仅续冻，不释放
履约完成(FINISHED) → 结算冻结期(24h/纠纷挂起, HOLD) → 唯一解冻分账节点
分账: 律所对公账户(律师费) + 平台服务费(费率版本化) + 缺席分成
违约扣减: 分账前从律所在持牌机构的待结算余额扣减
        → 不足部分由支付机构侧托管的保证金专户补足(§4.4-保证金)
```

- **保证金（v2.0 修正，PRD 未定义 → 显式设计决策）**：律师入驻时经持牌支付机构分账体系冻结小额保证金，托管于**支付机构侧保证金专户**——平台仅持指令权与台账，不自收、不碰资金；违约金（律师<24h 取消 20%/缺席 50%）按上述扣减顺序执行，全额按用户支付占比补偿用户（平台不抽佣）。金额与缴纳时点待产品确认（§10-4）。
- **缺席费用（PRD §8.5）**：70% 归律师；30% 经分账进入平台在持牌机构的**分账接收账户**，定性为"积分兑付备付金"——按未兑付积分余额 1:1 足额备付、不可挪用，积分抵扣下单时同步核销；积分 180 天到期作废后的资金归属为联合决策点（§10-1）。备选最彻底方案：30% 直接原路退款到场用户，积分与资金脱钩（需产品确认）。
- 平台只发指令、不持资金；对账文件（T+1）与本地 SplitLedger 双向核对，差异进工单（SLA：24h 内处置）。
- **幂等**：所有支付/退款/分账请求带业务幂等号（`payment_orders.idempotency_key` 唯一约束）；对账为最终兜底。
- 退款原路退回，1-3 个工作日。
- **结算冻结期**：FINISHED 后 HOLD 24h；存在未结纠纷工单则挂起该场结算（settlements.hold），纠纷关闭后释放——分账后无法追回，前置冻结是唯一防线。
- 1对1 复用同一支付通道（预付全额，实结多退少补，§4.1）。
- **支付前实名闸口**：下单链路强制校验实名完成（PRD §7.1.1）。

### 4.5 调度域（v2.0 重写）

**事实源 = DB 到期任务表，延迟消息仅作低延迟优化**（不依赖 RocketMQ 延迟消息承载 24h/12h 定时——开源 4.x 固定级别最大 2h，5.x/商业版才支持任意时刻）：

- `schedule_jobs(id, job_type, ref_id, due_at, status, version)`；业务状态迁移在同一事务内写入/作废对应 job。
- 自研轻量调度器（TS，ADR-0003）每 10–15s 多节点 `SELECT ... FOR UPDATE SKIP LOCKED` 抢占到期的 job，执行器幂等回查当前状态（人工操作可能已使任务过期）。
- ~~XXL-Job 与 TS 后端（NestJS）的触发通路待裁决（ADR-0001）~~ → **已裁决（ADR-0003，v2.2）**：弃用 XXL-Job，改自研轻量调度器，调度器与 Core 同进程，原「HTTP 回调 Core 内部端点 vs Java shim executor」跨进程触发通路议题随之消解；调度事实源（DB 到期任务表）与执行器语义不变。
- RocketMQ 延迟消息仅用于 1min/10min 级低延迟提醒推送，丢失不影响正确性（job 仍在 DB 兜底）。
- **宽限期与缺席判定一律锚定约定开始时刻**（而非 opened_at）——开房延迟不吞宽限期，杜绝误判缺席；开房 job 必须准点，延迟 >30s 电话告警（与扫描周期 ≤15s 自洽）。
- 所有调度事件落 `schedule_job_log` 可重放。

| 事件 | 触发器 |
|---|---|
| 提醒 24h/1h/10min/1min | 开团成功时写 job（短时距叠加延迟消息优化推送） |
| 成团截止（流标判定） | 创建时按 deadline 写 job |
| 到点开房 | 准点 job → fulfillment 开房，宽限计时（锚定约定时刻） |
| 宽限期 5min / 缺席 15min 判定 | 两级 job，回查在场快照，写 Attendance |
| 无人到场 → 关闭 → 退款 | 宽限结束 job 判定全员缺席（含律师）→ 平台取消路径 |
| C2B 律师确认 12h 超时 | 延迟 job → 自动拒绝 + 信用事件 |
| 1对1 律师响应超时 / 服务超时实结 | 接单后 N 分钟 job；结束 + 30min 默认实结 job |
| 补偿 24h 发放 | 改价生效时投递 |
| 律所进件年度复验 | 每年至少 1 次（电商法 §27 核验义务） |
| 锁 reaper / 到期处置（§5.2） | 周期 job |

### 4.6 Agent 草稿气泡管线

```
房间用户消息(MQ) → 实时脱敏层(NER+规则→占位符, ≤1s)
→ 专项意图识别/问题聚类(≤1s) → RAG 检索(≤2s) → LLM 生成草稿(≤4s)
→ 长连接推送律师端气泡(合计≤8s P95) → 律师动作(发送/修改/丢弃)
→ AgentReviewLog 落库(草稿、修改diff、动作、耗时) → 看板(直接发送率/修改率/丢弃率)
```

- **实时脱敏层（v2.0 新增，合规 R4）**：与训练管线同源 NER+规则；姓名/证件/电话/地址→占位符后才进 RAG 与 LLM；律师端气泡显示占位符由律师自然表达。**敏感话术硬拦**（承诺结果/包赢类）不生成。
- **隔离铁律**：Agent 写路径与房间消息发送路径无共享写入点；发送动作=把草稿内容作为律师消息提交，经正常消息风控后再入房间。
- 语音/视频房间：草稿同一管线，律师端悬浮条/耳机 TTS 呈现（客户端职责）。
- 多用户并行：按 room_id 分区有序消费 + 每用户最新问题去重合并。
- 待办提示：drafts.answered 状态 + 未回应问题列表接口。
- LLM 故障降级：律师端显式"AI 辅助不可用"，不阻塞手打。

### 4.7 信用与权益

- **信用**：事件驱动（CreditEvent 不可变流水 + credit_accounts 快照，**唯一事实源**；lawyer_profiles.credit_score 读缓存为规划项，当前以 G1 /credit/score 查询面对外提供）。规则表驱动（PRD §8.8 全表），限制类后果（限制拼单、暂停接单）由信用模块发"限制令"，trade 模块入口校验。规则变更走 §4.3 规则版本化（公示≥7日，行为时快照）。
- **积分**：账户+流水；获取（补偿、缺席分成）与消耗（下单抵扣，100:1、单笔≤50%）双通道；180 天惰性过期 + 定时清理；**兑付备付台账**（§4.4）。
- **优惠券**：§4.3 最小化设计。
- 评价排序：review 输出律师综合评分入场次列表/接单大厅排序因子（权重可配置）。

### 4.8 会话与消息模型（v2.0 新增）

- `conversations(id, type[room|private|one_on_one], ref_id)` 统一三种会话；`messages.conversation_id` 替代 room_id。
- 1对1 订单支付成功 → fulfillment 自动创建 `type=one_on_one` 会话并绑定订单；履约、计量（RTC 时长回调）、实结都在此会话上闭环。
- 私聊（用户-律师）限平台内，同一风控链路（§6）；"系统自动私信未到者"（PRD §8.4）复用此通道或 notify 站内信（待产品定，§10-7）。
- 消息模型：`msg_id + 会话内单调 seq`；断线增量拉取；迟到回填；冷存（OSS）按会话/时段读取接口供导出与合规调取。

### 4.9 到场与缺席判定权威链路（v2.0 新增）

- RTC/IM 服务以 at-least-once MQ 事件上报 join/leave（带房间时刻戳）→ Core 幂等写 attendances（user_id + role）。
- 判定以**宽限结束时点的在场快照**为准，30–60s 抖动容忍（断网重连不误判）。
- 状态边界：宽限期内进入=normal；超宽限 ≤15min=late（旁听，不退费不重计时）；超 15min=absent（费用不退，70/30 分成 + 信用扣分）。
- **律师缺席前置校验**：判定前先校验开房 job 已成功——开房失败属平台故障，走"平台取消→全额退款→不扣律师信用"分支（PRD §8.7 复用），杜绝平台故障误判律师缺席（-50 分+50% 赔付）。

### 5.2 存储与合规设计（v2.0 全面修订）

- **留存期限（合规 R2）**：messages 热存 PG（90 天）→ 冷存 OSS，**自服务（交易）完成之日起不少于 3 年**（电商法 §31；法定留存义务构成 PIPL §13(三) 处理基础，法定期限为留存上限衔接最小必要）。1对1 录音录像：RTC 云录制 → OSS 合规 bucket（WORM/版本锁定），哈希上链存证，留存 ≥3 年；仅合规角色经审批调取（审计）+ **本人调取通道**（PIPL §45）。
- **到期处置作业**：OSS 生命周期规则到期自动删除或匿名化转统计；删除动作入审计。
- **实名（合规 R6）**：核验凭据双轨——对接公安 CTID/运营商三要素（通道待核实）后默认仅存核验结果+凭据摘要（KMS 信封加密+密钥轮换）；姓名/证件号密文仅在已声明目的（纠纷处理）下经审批+双人复核临时解密；consents 记录实名单独同意；license_no 纳入列加密。
- **手机号**：列加密 + HMAC 盲索引（检索用）。
- **训练数据（合规 R3）三层授权**：① 首次成团/支付流程内**独立授权页**（可拒绝，拒绝不影响拼单与房间功能，仅该房间消息不进训练语料库）；② consents 表记录（scope=training）+ 策略版本；③ 设置中心可撤回，撤回后未训练样本经 source_msg_id 反查物理删除；已参与训练的模型版本处置标注联合决策点（§10-6）。脱敏输出定性为**去标识化数据（仍属个人信息）**，仅限平台内部训练、不出库不共享；达到匿名化标准前，V3"数据资产产品化"不得对外提供语料。
- **导出（合规 R10）分级导出**：本人消息全量 + 他人消息默认去标识（昵称/ID 掩码、正文保留以维持证据上下文，导出包附告知）；实名信息与录音不在默认范围（录音走本人单独申请）；导出请求入审计；异步加密包 + 限时下载链接。
- **数据分类分级目录（合规 R19）**：L4 敏感（实名/支付/咨询内容/录音）差异化管控（加密、审批、审计）；L3 行为数据；L2 公开配置。
- **律所授权文件**（合规 R20）：入加密 OSS 资料库；RAG 语料记录内容来源与授权状态（律师回答模板知识产权归属在入驻协议明确，数据模型登记授权位）。
- **迁移/备份**：Flyway/Liquibase 版本化（候选基线，最终随 M0-1 遗留子项裁决，偏离须回写本节脚注——ADR-0001）；PITR 备份，日全量+WAL。

## 7. 部署与可观测

### 7.1 部署（V1，v2.0 补 HA 拓扑）

- 全量容器化，单区域双可用区；K8s（或过渡期 ECS+Docker Compose），基础设施即代码从第一天 Helm/Terraform。
- **最低 HA 拓扑（支撑 99.9%）**：
  - Core API ≥2 副本，滚动发布 + 连接 draining；
  - PostgreSQL 云 RDS Multi-AZ（或 Patroni）；
  - RocketMQ 多副本；Redis 哨兵/集群；
  - 调度执行器多节点（SKIP LOCKED 抢占，天然消除调度单点）；
  - WSS 网关 ≥2 节点，房间成员关系落 Redis+DB，节点故障客户端重连任意节点+按 seq 补消息，房间态可重建。
- 环境 dev/staging/prod；配置中心 Nacos/Apollo。
- **门禁**：备案/许可未完成不进 prod（等保定级备案、ICP、增值电信许可、App 备案）；涉个人信息新功能 PIA 通过才可上线。

## 9. 关键风险与权衡

| 风险/权衡 | 说明与对策 |
|---|---|
| 单体过早拆微服务 | 已规避：模块化单体起步，模块边界有强制手段（§2.1 DB role+schema 权限、CI 静态检查） |
| 自研 IM vs 第三方 | 自研文本 WSS（房间即会话，无漫游复杂需求）；音视频直接 RTC 厂商。**切换标准**：需要已读回执/多端漫游/离线消息复杂度超过自研维护成本时切第三方 |
| 调度可靠性 | DB 到期任务表为事实源（可审计、可重放、无版本依赖），延迟消息仅优化；宽限期锚定约定时刻 |
| 分账合规依赖第三方 | 微信/支付宝双通道抽象，单通道故障可切换；对账为资金正确性兜底（SLA 24h） |
| LLM 草稿质量与延迟 | 实时脱敏层占预算 ≤1s；草稿异步生成不阻塞律师打字；AgentReviewLog 指标驱动提示词/知识库迭代；敏感话术词表硬拦；故障降级显式态 |
