# E3 专项配置与知识库

> 域：E-AI辅助 ｜ 架构模块：agent-assist + ops ｜ V1（配置能力） ｜ P1 ｜ 阶段：①基建/②联调
> 上游：运营后台（管理页） ｜ 下游：E1（RAG/提示词/硬拦词表）、C2（问题树引导）、H9（语料授权登记） ｜ 技能：P0六件套 + lj-data-security

## 1. 职责与边界
- 做：专项配置包管理（知识库文档上传/问题树编辑/提示词模板/风控词表引用）；语料授权状态登记；V2 多专项零代码上线基础。
- 不做：词库判定引擎（H5）；草稿生成（E1）。

## 2. 功能点
- 运营后台三页面：知识库文档上传（入库→分块→向量化）、问题树编辑（结构化标签）、提示词模板管理（版本化）
- 专项维度隔离：specialty=key（V1: labor_arbitration）
- **用户端垂直选择器数据源（2026-10-17 双维度框架；同日「应用做全套」口径）**：GET /specialty/list 返回配置包**全集**（含 active=false，附名称/状态）——应用侧全集渲染可选、不设灰置门槛；选择某垂直后内容有无由 active 与城市供给决定，无内容展示空态与引导（切回已上线垂直/发起拼团）；配置包上下线与供给开通=运营侧操作（04 §8-25）
- 语料授权登记：知识来源（官方/律所授权/脱敏语料）+授权状态位

## 3. 领域模型
specialty_configs(id PK, specialty varchar(32) UNIQUE, question_tree jsonb NOT NULL, prompts jsonb NOT NULL, active bool)
knowledge_docs(id PK, specialty, title, source_type varchar(16),  -- official|firm_authorized|anonymized
  license_status varchar(12), file_ref text, uploaded_by, created_at)
knowledge_chunks(id PK, doc_id, chunk text, embedding vector(1024),  -- pgvector
  metadata jsonb)
CREATE INDEX ix_chunks_vec ON knowledge_chunks USING ivfflat (embedding vector_cosine_ops);

## 4. 关键流程
上传 → 解析（pdf/docx/md）→ 分块（512 token 重叠 64）→ 向量化（境内 embedding ⚠同 E1 约束）→ 入库；文档禁用即检索过滤。

## 5. 接口契约
| POST | /admin/specialty/{key}/knowledge | {file_ref, source_type, license_status} | {doc_id} | 400 BAD_FORMAT | 幂等键=file_hash
| PUT  | /admin/specialty/{key}/question-tree | {tree} | {version} | 400 INVALID_TREE | 幂等键=key+base_version
| PUT  | /admin/specialty/{key}/prompts | {prompts} | {version} | - | 幂等键=key+base_version
| GET  | /specialty/question-tree?key= | - | 树结构（C2 消费，公开只读） | - | 否
| GET  | /specialty/list | - | 配置包**全集**（key/名称/active 含 false——用户端垂直选择器数据源，全集渲染空态由内容驱动，2026-10-17「应用做全套」口径） | - | 否 |
检索内部 API：E1 调用（top_k=8，cosine）。

## 6. 领域事件
- 生产：KnowledgeUpdated{specialty}（→E1 缓存失效）；QuestionTreeUpdated{specialty, version}（→C2）。
- 消费：无。

## 7. 业务规则
- R-01 专项差异收敛为配置包（知识库+问题树+提示词+词表引用），V2 新专项零代码 ｜架构 §8
- R-02 语料授权状态登记（律师回答模板 IP 归属入驻协议明确）｜PRD §10.3、架构 §5.2 合规 R20
- R-03 提示词模板变更只影响后续生成 ｜架构 §4.6
- R-04 V2 才新增专项；V1 仅 labor_arbitration ｜PRD §1.6

## 8. 非功能要求
- 检索 P95 ≤2s（E1 预算内）；文档上传异步处理（≤5min）；向量化供应商同 LLM 合规约束。

## 9. AI 开发标准（本模块附加）
- TDD：分块确定性（同文件同分块）、树结构校验、缓存失效、禁用文档不出现在检索结果；
- 禁止：未登记授权状态的语料入检索池；embedding 用境外 API。
