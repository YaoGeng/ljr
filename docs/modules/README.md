## 模块文档标准模板（头部引用块 + 11 个编号节，与 42 篇实文一致）

**头部引用块（模块概览，不占节号）**：域/架构模块与 schema 归属/版本/优先级/施工阶段/上下游依赖/必载技能

1. **职责与边界**（做什么/不做什么/边界纪律——越界即 reject）
2. **功能点清单**（含三端 UI 对应：用户端/律师端/后台）
3. **领域模型（DDL 级）**（表/字段/类型/约束/索引；金额一律 NUMERIC(12,2)，时间一律 timestamptz，时区 Asia/Shanghai）
4. **状态机与关键流程**（状态集/迁移守卫/伪代码或流程图）
5. **接口契约**（REST/WSS/MQ：方法、路径、入参、出参、错误码、幂等键）
6. **领域事件**（生产/消费：事件名、载荷字段、投递语义 at-least-once、消费幂等键）
7. **业务规则**（R-01 编号 + 公式/算法 + 溯源 PRD §x / 架构 §y）
8. **非功能要求**（性能预算/可用性/安全合规，映射架构 §1.2/§6/§7）
9. **AI 开发标准（本模块专属）**（见下方总纲 + 模块附加项）
10. **验收清单**（可测判据 checkbox；跨阶段依赖项标注桩方案）
11. **待澄清点**（无则写"无"；继承项标注 04 §8 编号）

## AI 开发标准总纲（所有模块通用，模块文档只写附加项）

### 装载（按施工阶段，引用 docs/03 技能指南 §9.2）
- 全程：superpowers P0 六件套（TDD、systematic-debugging、verification-before-completion、writing-plans、requesting-code-review、receiving-code-review）
- 按域附加自建技能：trade/schedule/pricing/fulfillment/identity → lj-domain-rules；payment/settlement → lj-payment-invariants；identity/agent-assist/存储 → lj-data-security + lj-compliance-guards；履约/信用/支付测试 → lj-test-matrix

### 五条产线纪律
1. **TDD 先行**：模块文档 §7 规则表 → 先写失败测试清单（每条 R-xx 至少 1 个用例）→ 再写实现；
2. **完成必须有证据**：verification-before-completion——完成声明必须附测试/构建执行证据（命令+输出），禁止"应该能跑"；
3. **审查闭环**：提交前 requesting-code-review；模块涉及 payment/settlement/信用 时必须交叉审查（另一 agent 按 lj-payment-invariants 清单审）；
4. **边界纪律**：只写本模块 schema 的表；跨模块取数走接口或事件消费，发现需要跨表 join 即停下来在 PR 中提出；
5. **禁止事项通则**：金额禁 float（NUMERIC）；状态字段禁裸写（必须经状态机守卫+迁移日志）；密钥/证书禁入代码与 skill；生产支付通道禁封装为 agent 可调用工具；PRD/架构未定义的行为不得自行发明（列入待澄清并按 04 §8 处理）。

### 通用验收门（每个模块必须过）
- [ ] §10 验收清单全绿（含桩方案项）
- [ ] 诊断零 error（lsp_diagnostics）
- [ ] 相关测试套件一次通过（运行器按模块技术栈：前端/Node 侧默认 bun test；NestJS 侧 vitest 或 jest 由脚手架统一后固定，全仓不混用）
- [ ] PR 含：变更说明、测试证据、schema 迁移脚本（如有）、lj-* 技能同步检查单（如规则变更）
