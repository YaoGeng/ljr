# C6 改价与补偿

> 域：C-交易 ｜ 架构模块：pricing + benefits ｜ V1 ｜ P0 ｜ 阶段：①（审批走 H3 人工兜底，②接工单）
> 上游：B3（新版本）、C3（在团判定数据）、H3（审批） ｜ 下游：G1（信用）、F4（积分/券补偿）、I1（三档话术）、H7（规则版本） ｜ 技能：P0六件套 + lj-domain-rules + lj-payment-invariants + lj-test-matrix

## 1. 职责与边界
- 做：改价规则引擎（在团判定→分级处理→频率限制→撤销→补偿计算与发放指令→PricingHistory）；三档通知话术渲染。
- 不做：积分/券发放执行（F4）；信用执行（G1）；默认价存储（B3）。

## 2. 功能点
- 改价申请（基于 B3 新版本草案）→ 引擎判定（见流程）
- 频率窗口（30 天 3 次）；超限审批流（H3；①期人工兜底）
- 24h 撤销（恢复上一版本，不扣信用，通知受影响用户）
- 补偿计算：积分（+降价>10% 档加优惠券），24h 内发放

## 3. 领域模型
pricing_histories(
  id bigserial PK, lawyer_id bigint NOT NULL,
  old_version int NOT NULL, new_version int NOT NULL,
  direction varchar(8) NOT NULL,               -- UP|DOWN
  change_pct numeric(6,3) NOT NULL,            -- |新-旧|/旧
  has_active_group boolean NOT NULL,           -- 在团判定
  approval_id bigint NULL, credit_penalty smallint NOT NULL DEFAULT 0,
  created_at timestamptz, revoked_at timestamptz NULL,
  CHECK (change_pct >= 0)
)
补偿流水由 F4 承载（points_txns source=price_compensation；coupon_grants source=price_compensation）。

## 4. 关键流程（引擎判定）
输入：old/new 价 + has_active_group
1. has_active_group=false → 生效，无惩罚，通知新价
2. has_active_group=true：
   UP（涨价）→ 生效；已锁定用户按快照；新发起按新价；信用-5
   DOWN ≤10% → 需审批；快照保护+积分补偿；信用-15
   DOWN >10% → 需审批；快照保护+积分补偿+优惠券；信用-30 + 暂停接单 3 天
3. 频率检查：30 天 3 次（Redis 滑动窗口+DB 复核）→ 超限走审批（无论方向）
4. 补偿对象：所有已支付且未完成服务用户；金额 = (原价-新价) × 用户已支付金额占比
5. 撤销：24h 内恢复上一版本，revoked_at 记录，通知；超 24h 拒绝

## 5. 接口契约
| POST | /lawyer/pricing/change | {new_version_draft} | {result: EFFECTED|PENDING_APPROVAL|REJECTED, history_id?} | 429 FREQ_EXCEEDED | 幂等键=lawyer+new_version
| POST | /pricing/change/{id}/revoke | - | {status} | 409 PAST_24H | 幂等键=history

## 6. 领域事件
- 生产：PriceChangeApproved{lawyer_id, history_id, direction, change_pct}（→G1 信用、F4 补偿、I1 话术、B3 生效）；PriceChangeRejected{...}；PriceRevoked{...}。
- 消费：TicketResolved（H3 审批结果）。

## 7. 业务规则
- R-01 三档矩阵：UP -5；DOWN≤10% 审批+积分 -15；DOWN>10% 审批+积分+券 -30+停接 3 天 ｜PRD §8.2
- R-02 已锁定用户不受改价影响（快照）｜PRD §8.2
- R-03 频率：30 天最多 3 次（含涨降）；超限审批；恶意频繁改价 -20/严重停接 ｜PRD §8.2
- R-04 撤销 24h 内，不扣信用，通知受影响用户 ｜PRD §8.2
- R-05 补偿 = (原-新) × 支付占比；24h 内发放（积分 1 元=100 分，180 天有效）｜PRD §8.2
- R-06 话术三档（涨价/降价/大幅降价）按 PRD §8.2 模板，I1 渲染 ｜PRD §8.2

## 8. 非功能要求
- 引擎判定 P95 ≤200ms；频率窗口 Redis+DB 双查；补偿发放 24h SLA（巡检告警）。

## 9. AI 开发标准（本模块附加）
- 交叉审查强制（补偿计算涉资损）；
- TDD（lj-test-matrix）：三档全矩阵（10.0% 边界）、频率第 4 次、撤销 24h 边界、补偿占比计算（分母=paid_amount 全额 cash+points/100，口径已裁决见 §11）；
- 禁止：补偿金额 float；改价直接改 price_versions 历史行。

## 10. 验收清单
