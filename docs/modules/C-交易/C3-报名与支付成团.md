# C3 报名与支付成团

> 域：C-交易 ｜ 架构模块：trade + payment ｜ V1 ｜ P0 ｜ 阶段：①（积分抵扣用例②补验）
> 上游：A2（实名闸口）、G1（限制校验）、F4（积分抵扣切片）、C1/C2（标的）、H1（卡片实力摘要，2026-10-16 增量） ｜ 下游：F1（支付）、I2（成团 job 预写）、I1（成团通知） ｜ 技能：P0六件套 + lj-payment-invariants + lj-domain-rules + lj-test-matrix

## 1. 职责与边界
- 做：报名下单（快照价）、实名/信用闸口校验、成团原子守卫、截止竞态兜底、我的报名视图。
- 不做：支付通道执行（F1）；退款执行（F2）；快照生成后的价格解释（B3）。

## 2. 功能点
- 浏览（仅过审律师）：列表卡片附律师实力摘要（同 C1 口径——批量调 H1 GET /lawyers/{id}/profile/summary，禁直查 ops schema；2026-10-16 PRD §7.1.2 增量）
- 报名拼单（session）/加入拼团（group_buy）：按快照价创建支付单（cash+points 拆分）
- 闸口：实名 VERIFIED、G1 限制令、截止前 30s 停开新单
- 成团守卫（原子 SQL）+ 成团通知 + I2 提醒 job 预写
- 兜底：支付回调到达时实体已终态（FAILED/FULL/EXPIRED）→ 自动退款分支

## 3. 领域模型
enrollments(
  id bigserial PK, ref_type varchar(16) NOT NULL, ref_id bigint NOT NULL, user_id bigint NOT NULL,
  price_snapshot jsonb NOT NULL,               -- {price_mode, unit_price, share_price, session_total, price_version, snapshot_at}

  cash_amount numeric(12,2) NOT NULL DEFAULT 0, points_amount int NOT NULL DEFAULT 0,

  credit_used int NOT NULL DEFAULT 0,          -- 本单积分抵扣
  reschedule_used boolean NOT NULL DEFAULT false,
  prev_enrollment_id bigint NULL,              -- 转化/改期迁移链（新建行回链）
  created_at timestamptz

CREATE UNIQUE INDEX ux_enroll_active ON enrollments(ref_type, ref_id, user_id)
  WHERE pay_status IN ('PENDING','PAID');      -- 活跃态唯一：同场次同用户仅一条活跃报名（取消/终态后可重报，历史行保留）
state_transition_log(id, entity_type, entity_id, from_status, to_status, reason, job_id, created_at)

## 4. 关键流程（成团原子守卫）
支付成功回调（F1→Inbox→本模块）：
  BEGIN;
  UPDATE sessions SET joined = joined + 1
    WHERE id = ? AND status = 'CREATED' AND joined < capacity RETURNING joined;
  -- 更新 0 行 ⇒ 满员/终态 ⇒ 走自动退款分支（写 state_transition_log）
  INSERT enrollments(...PAID...); COMMIT;
group_buy 同理（joined 与 sub_min 比较；REACHED 后 I2 投 12h 确认 job）。

## 6. 领域事件
- 生产：EnrollmentPaid{ref_type, ref_id, user_id, amounts}；SessionFull/GroupBuyReached；SessionFailed（截止 job 协同）。
- 消费：PaymentCallbackInboxed（F1）；RestrictionIssued（G1，入口校验）；LawyerAuditPassed（A3a——过审律师进入可浏览列表）；LawyerProfileTakedown（H1——档案下架时卡片实力摘要隐藏/缓存失效）。

## 7. 业务规则
- R-01 支付即冻结（F1 冻结指令）；未成团自动退款 ｜PRD §7.1.4
- R-02 成团即锁人不补不退 ｜PRD §8.1
- R-03 快照价：用户支付时看到多少付多少；改价不影响 ｜PRD §8.2/§9.1
- R-04 积分抵扣：100 积分=1 元，单次 ≤ 订单金额 50%；cash+points=应付 ｜PRD §8.2、架构 §4.7
- R-05 截止前 30s 停止新建支付单；回调遇终态自动退款 ｜架构 §4.1
- R-06 实名闸口 ｜PRD §7.1.1、架构 §4.4

## 8. 非功能要求
- 守卫 SQL 行锁竞争下 P95 ≤80ms；回调处理幂等（Inbox 幂等号）；自动退款分支 100% 触发（资损不变量巡检兜底：已支付+终态+未退款>10min 告警）。

## 9. AI 开发标准（本模块附加）
- 交叉审查强制（lj-payment-invariants 清单：幂等键、守卫 SQL、竞态兜底）；
- TDD（lj-test-matrix）：并发 2×capacity 支付恰 capacity 成功+其余退款、R-04 抵扣边界（50% 整/零头）、R-05 30s 边界；
- 禁止：先插 enrollment 后改 joined（顺序反了必超卖）；points 换算用 float。
