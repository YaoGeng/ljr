# C7 快速1对1解答（抢单报价）

> 域：C 交易｜架构模块：trade（主属）+ fulfillment/payment 复用｜版本：V1.5（产品扩展批，PRD 2026-10-22 增补 §6.6/§7.1.9/§7.2.9/§8.9/§9.6）｜优先级：P1｜施工阶段：⑤（05 §7.5 M3.5-W1）｜**2026-10-23 拍板修订（D25）：律师每日报价 10 次+联系方式对律师不可见（订阅解锁，D22 翻转）——R-05 重写、R-09/R-10 新增｜同日 #50 收口：钩子定价 ¥48.8/月（暂定）·订阅档 30 次/日·计数/查看时点/载体/时机/清单按推荐**
> 上下游：上游=A1（登录/角色）、A2（支付实名闸口）、E3（问题树引导）、G1（限制令入口校验）；复用=D6（one_on_one 履约全套）、D5（会话）、F1/F2/F3（支付/退款/实结）、G2（双边评价）、I1/I2（通知/超时 job）；下游=H4（快速单指标）、H1（实力档案报价响应统计）
> 必载技能：superpowers P0 六件套 + lj-domain-rules + lj-payment-invariants（资金面交叉审查强制）+ lj-test-matrix

## 1. 职责与边界

- 承载快速咨询单的交易段：发单（问题标签+≤30min+联系方式提供）→ 征集报价 → 用户选定 → 支付 → 落 one_on_one_orders(source=quick) 移交履约；律师侧承载**每日报价次数配额（10 次/日）与订阅会员门**（联系方式查看+次数提升，2026-10-23 拍板）。
- **价格不公布为查询面硬约束**：报价金额仅发单用户与报价律师本人可读（成员门 fail-closed，同 D5 四口成员门模式）。
- 履约/计量/实结/取消三档**全部复用 D6**：本模块 PAID 后在 fulfillment 创建 one_on_one_orders（source='quick'，price=报价，duration_cap=30min），不新写履约状态机；实结=报价一价包干（consumed_units 不参与金额）。
- 不做：1对1 预设价目矩阵（B3/D6 既有入口）；会话与消息（D5）；结算状态机（F3 消费 OneOnOneSettled net 基——#45-① 已闭合口径直接复用）。

## 2. 功能点清单

- 用户端：发起快速单（问题树引导标签+描述+沟通偏好+联系方式提供[加密存储，用于纠纷/客服联系与订阅律师查看]）、我的快速单列表、报价对比与选定、支付、会话入口、双边评价入口。
- 律师端：抢单大厅快速单区（仅见问题面，**无任何报价金额、无用户联系方式**——联系方式=订阅律师解锁查看项，顶部展示「今日剩余报价次数 X/10」）、提交报价（金额+一句话说明；受每日次数配额闸）、撤回重报、被选定通知、会话入口、评用户入口。
- 订阅面（会员钩子，#50 已收口）：¥48.8/月（暂定）——次数档位提升（10→30 次/日）+联系方式查看解锁的会员状态展示与开通入口。
- 后台：指标入 H4（响应率/被选率/成交率/首报价时长）；纠纷走 H3 既有工单。

## 3. 领域模型（DDL 级，schema=trade）

```sql
quick_orders (
  id             uuid PK,
  user_id        uuid NOT NULL,
  specialty      varchar(32) NOT NULL,
  city           varchar(32) NOT NULL DEFAULT '北京',
  question_tags  jsonb NOT NULL,          -- E3 问题树引导标签
  qnote          varchar(2000),
  mode           varchar(8) NOT NULL DEFAULT 'text',   -- text | voice（期望沟通形式）
  duration_cap   interval NOT NULL DEFAULT interval '30 min',
  contact_visible boolean NOT NULL DEFAULT true,    -- 2026-10-23 语义重定义：用户是否提供联系方式（供纠纷/客服与订阅律师查看）；false 时 contact_enc 为 NULL
  contact_enc    bytea,                   -- 列加密（PIA 触发面，02 §6）；对律师默认不可见——订阅会员门（2026-10-23 拍板，翻转 D22「明示可见」）
  awarded_bid_id uuid,
  status         varchar(24) NOT NULL,    -- 状态机经守卫，禁裸写
  close_at       timestamptz,
  created_at     timestamptz NOT NULL DEFAULT now()
);
quick_bids (
  id         uuid PK,
  order_id   uuid NOT NULL REFERENCES quick_orders(id),
  lawyer_id  uuid NOT NULL,
  amount     numeric(12,2) NOT NULL CHECK (amount > 0),
  note       varchar(200),
  status     varchar(16) NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE|WITHDRAWN|AWARDED|LOSEN
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (order_id, lawyer_id)          -- 同单同律师唯一：重报=撤回旧行再新建
);
```

## 4. 状态机与关键流程

```
CREATED(征集报价中) → AWARDED(选定) → PAID(支付) → 履约移交(fulfillment one_on_one_orders)
CREATED → CLOSED(征报价超时 D_QUICK_COLLECT=24h[已拍板 D22] / 用户关闭)
AWARDED → CLOSED(支付前放弃；AWARDED 未支付态带 15min TTL 自动回落/关闭 ⚠ 施工定)
PAID → LAWYER_TIMEOUT(律师超时未开始，复用 D6 接单超时口径[已拍板 D22]) → REFUNDED
```

- 流程：发单（G1 限制令校验+实名可后置到支付）→ 律师报价（同一律师同单恰一个 ACTIVE；**前置每日次数配额闸=当日成功报价数 <10 次，订阅档位覆盖，R-09**）→ 用户选定（AWARD 原子守卫：仅本人+单在 CREATED+bid 在 ACTIVE，同事务落 awarded_bid_id+其余 bid 置 LOSEN）→ 支付（F1 下单，幂等键=quick:{order_id}，实名闸口）→ PAID 同事务调 fulfillment 导出面创建 one_on_one_orders(source='quick')（复用 C4/C7→fulfillment 单向导出先例，禁跨 schema 直写）→ OneOnOnePaid 事件驱动 D5 建会话（既有链）→ 30min 上限由 D6 计量上界承载。
- 律师超时未开始：复用 D6 LAWYER_TIMEOUT 语义（全额退款+信用 -5），C7 侧仅同步快速单终态展示。

## 7. 业务规则

- **R-01 时长上限**：会话 ≤30 分钟（duration_cap 固定，锚定会话开始时刻，到时自动结束——D6 计量上界承载）。〔PRD §8.9〕
- **R-02 价格不公布**：报价金额仅发单用户与报价律师可读（§5 成员门）；任何通知/文案不得含金额。〔PRD §8.9〕
- **R-03 恰一报价**：同单同律师唯一 ACTIVE 报价；AWARDED 前可撤回重报；LOSEN/AWARDED 不可撤。〔PRD §8.9〕
- **R-04 征报价超时**：CREATED 持续 D_QUICK_COLLECT（24h，已拍板 D22）无 AWARD → 自动 CLOSED（未支付零资金占用）。〔PRD §8.9〕
- **R-05 联系方式**：contact_visible=true 时 contact_enc 必填（列加密+盲索引）；**对律师一律不可见为默认——仅订阅律师（会员）可经独立端点脱敏+一键查看（留痕审计）**（2026-10-23 拍板，翻转 D22「明示=对可报价审核律师可见」）；false 时字段物理为 NULL。〔PRD §8.9/§14；02 §6 PIA〕
- **R-06 一价包干**：实结=报价金额，consumed_units 不参与金额计算（与 B3 预设价「多退少补」的关键差异）；取消/超时按 D6 三档（source=quick 同式）。〔PRD §9.6〕
- **R-07 入口校验**：发单与报价均过 G1 限制令；报价仅限过审律师（audit_status=PASSED）。〔PRD §8.9〕
- **R-08 双边评分**：FINISHED 后双方互评（G2 既有四维+匿名口径），评价入双方信用。〔PRD §8.9〕
- **R-09 每日报价次数**：律师每日提交快速单报价上限 **10 次**（D_QUICK_BID_DAILY 走 H7 配置化；计数口径=提交报价动作计数、撤回重报计入、被选定不另计——#50-① 收口；订阅档位覆盖限额=**30 次/日**（#50-③ 收口，H7 配置化默认 ⚠ 翻转不改结构）；自然日=Asia/Shanghai）。〔PRD §8.9；2026-10-23 拍板〕
- **R-10 订阅会员门**：联系方式查看与次数提升以律师会员状态为门（04 §8-21 快速单钩子；**钩子档定价=¥48.8/月（暂时口径，#50-③ 收口）**；会员载体=以 G1 律师面扩展查询位最小承接（#50-④ 收口），具体落法（列 vs 表）=本模块施工卡定，不另立模块不建独立表）；会员门 fail-closed。〔2026-10-23 拍板+同日收口〕

## 8. 非功能要求

- 抢单大厅读 P95 ≤300ms；AWARD/PAY 原子守卫并发安全（同 C3 守卫标准）。
- contact_enc 走 KMS 信封加密（同 real_name_infos 双轨口径）；日志/事件载荷禁出现联系方式明文。

## 9. AI 开发标准（本模块附加）

- 资金面（pay/LAWYER_TIMEOUT 退款）强制交叉审查（lj-payment-invariants）；金额经 Money 工具。
- hall 查询面 DTO 不含 amount 的断言写成**结构测试**（序列化快照），防演进回归。
- 全部律师读面 DTO 不含联系方式的断言同上写成结构测试；订阅查看端点留痕审计日志（谁在何时查看哪单的联系方式）。
- source='quick' 枚举扩展须与 D6 模块文档同步（跨模块会签）。
