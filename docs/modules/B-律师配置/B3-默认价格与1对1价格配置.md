# B3 默认价格与1对1价格配置

> 域：B-律师配置 ｜ 架构模块：pricing ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：- ｜ 下游：C1/C2（取默认值）、C6（改价引擎基线）、I1（版本变更通知）、F3（1对1 结算价） ｜ 技能：P0六件套 + lj-domain-rules + lj-payment-invariants

## 1. 职责与边界
- 做：默认人头价/场次总价/开团固定人数/接受拼团范围/房间沟通形式（多选）/1对1 价格矩阵的版本化配置；区间校验；修改通知。
- 不做：改价规则判定（C6）；价格快照（C3 支付时固化）。

## 2. 功能点
- 配置修改产生新 PriceVersion（旧版本不可变）
- 1对1 价格区间校验：文字 50-300 元/次；语音/视频 100-500 元/15min
- 修改默认价格 → 通知已参与拼团用户（I1）

## 3. 领域模型
price_versions(
  id bigserial PK, lawyer_id bigint NOT NULL, version int NOT NULL,
  per_head numeric(10,2) NULL,                -- 人头价（二选一计价模式）
  session_total numeric(10,2) NULL,           -- 场次总价
  group_size smallint NULL,                   -- 开团固定人数
  accept_min smallint NULL, accept_max smallint NULL,   -- 接受拼团范围
  room_modes varchar(32)[] NULL,              -- text|voice|video 多选
  one_on_one_prices jsonb NOT NULL,           -- {text:{per_round:250}, voice:{per_15min:200}, video:{...}}
  created_at timestamptz, UNIQUE(lawyer_id, version)
)
约束（CHECK）：per_head 与 session_total 二选一非空；accept_min ≤ accept_max；one_on_one 区间校验（应用层+DB CHECK）。

## 4. 关键流程
- 修改 = 新版本插入（version+1）+ I1 通知已参与用户 + C6 改价引擎接管（若在团）。

## 5. 接口契约
| GET  | /lawyer/{id}/pricing | - | 当前版本全量 | - | 否
| PUT  | /lawyer/pricing | 全量新配置 | {version} | 400 OUT_OF_RANGE / 409 IN_GROUP_CHANGE（转 C6 流程） | 幂等键=lawyer+base_version
| GET  | /lawyer/{id}/pricing/history | - | 版本列表 | - | 否

## 6. 领域事件
- 生产：PriceVersionCreated{lawyer_id, version}。
- 消费：C6 的在团改价判定结果（PriceChangeApproved/Rejected）回流展示。

## 7. 业务规则
- R-01 计价模式二选一：per_head（用户付固定单价，律师收入=单价×实际成团人数）或 session_total（C2B 分摊额=总价÷子范围最低人数；律师收入=分摊额×实际成团人数）｜PRD §9.1
- R-02 1对1 价格区间：文字 50-300/次、语音视频 100-500/15min ｜PRD §9.3
- R-03 版本不可变；修改只影响后续新场次/新拼团，已锁快照不变 ｜PRD §8.2、架构 §4.3
- R-04 修改默认价格（有进行中拼团时）必须走 C6 引擎（本模块只接收结果）｜PRD §8.2

## 8. 非功能要求
- 配置读缓存（当前版本 Redis 60s）；写并发以 base_version 乐观锁防覆盖。

## 9. AI 开发标准（本模块附加）
- TDD：区间校验全矩阵（R-02 边界 49/50/300/301）、二选一约束、版本不可变；
- 禁止：金额 float（NUMERIC 硬规则）；直接 UPDATE 已有版本行。
