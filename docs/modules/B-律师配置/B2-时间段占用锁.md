# B2 时间段占用锁

> 域：B-律师配置 ｜ 架构模块：schedule（机制服务，被 C1/C2/C5 调用） ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：C1（B2C 创建即锁）、C2（发布即 PENDING_PAYMENT）、C5（改期新段） ｜ 下游：I2（TTL/reaper job）、G1（滥用事件）、B1（状态视图） ｜ 技能：P0六件套 + lj-domain-rules + lj-test-matrix

## 1. 职责与边界
- 做：具体场次时刻的占用锁（唯一事实源）；同事务加锁/释放；TTL；滥用防护；reaper 兜底。
- 不做：场次业务状态（trade 域）；锁的业务含义解释（调用方负责）。

## 2. 功能点
- 机制 API：LOCK_SLOT / RELEASE_SLOT / CONFIRM_PAYMENT（PENDING_PAYMENT→LOCKED）/ START_OCCUPY（LOCKED→OCCUPIED）
- 滥用防护：C2B 发布锁绑定支付单 + 10min TTL；每用户对同一律师进行中锁 ≤1、全局 ≤3
- reaper：扫描活跃锁 + 关联实体已终态超阈值 → 释放 + 告警

## 3. 领域模型
slot_locks(
  id bigserial PK,
  lawyer_id bigint NOT NULL, slot_start timestamptz NOT NULL,
  status varchar(20) NOT NULL,  -- PENDING_PAYMENT|LOCKED|OCCUPIED|RELEASED
  ref_type varchar(16) NOT NULL,  -- session|groupbuy|reschedule
  ref_id bigint NOT NULL, initiator_user_id bigint NOT NULL,   -- 发起人（滥用防护计数用）
  payment_order_id bigint NULL, ttl_at timestamptz NULL,
  created_at timestamptz
)
CREATE UNIQUE INDEX ux_slot_active ON slot_locks(lawyer_id, slot_start)
  WHERE status IN ('PENDING_PAYMENT','LOCKED','OCCUPIED');   -- 部分唯一索引=物理防线
CREATE INDEX ix_slot_ttl ON slot_locks(ttl_at) WHERE status = 'PENDING_PAYMENT';
CREATE INDEX ix_slot_user ON slot_locks(initiator_user_id) WHERE status IN ('PENDING_PAYMENT','LOCKED','OCCUPIED');

## 4. 状态机
PENDING_PAYMENT →(支付成功回调, CONFIRM_PAYMENT) LOCKED →(开房, START_OCCUPY) OCCUPIED →(场次终态, RELEASE_SLOT) RELEASED
PENDING_PAYMENT →(TTL 到期/reaper) RELEASED
LOCKED →(流标/拒绝/超时/取消, 同事务) RELEASED

## 5. 接口契约（内部机制 API，不暴露 HTTP）
| 调用 | 入参 | 出参 | 语义
|---|---|---|---
| LOCK_SLOT(lawyer_id, slot_start, initiator_user_id, ref_type, ref_id, payment_order_id?) | - | lock_id 或 SLOT_TAKEN / SLOT_ABUSE_LIMIT | 与业务实体同事务执行；同事务内按 ix_slot_user 计数校验 R-03，超限即拒并发 SlotAbuseDetected
| CONFIRM_PAYMENT(payment_order_id) | - | ok / NOT_FOUND | 支付回调事务内调用
| RELEASE_SLOT(ref_type, ref_id, reason) | - | ok / ALREADY_RELEASED | 幂等；与业务终态同事务

## 6. 领域事件
- 生产：SlotLocked{lawyer_id, slot_start, ref}；SlotReleased{..., reason}；SlotTtlExpired{...}；SlotAbuseDetected{user_id, lawyer_id}（→G1）。
- 消费：I2 TTL job（到期 PENDING_PAYMENT → 释放）。

## 7. 业务规则
- R-01 同一律师同一时间段只能存在一个有效场次（部分唯一索引兜底，DB 是唯一事实源；Redis 前置锁仅性能优化）｜PRD §6.5、架构 §4.2
- R-02 锁状态迁移与业务状态迁移同一 DB 事务（流标/拒绝/超时/取消同步释放；领域事件只通知下游）｜架构 §4.2
- R-03 C2B 滥用防护：PENDING_PAYMENT 纳入唯一索引 + 10min TTL 自动释放；每用户对同律师进行中锁 ≤1、全局 ≤3（同事务内按 ix_slot_user 计数，超限返 SLOT_ABUSE_LIMIT + SlotAbuseDetected 事件）｜架构 §4.2
- R-04 reaper：活跃锁 + 关联实体终态超阈值（15min）强制释放并告警（锁泄漏兜底）。扫描说明：PENDING_PAYMENT 走 ttl_at 部分索引；LOCKED/OCCUPIED 为全量扫描（V1 活跃锁 ≤万级，每 5min 一轮预算可接受；量级增长后补 created_at 部分索引）｜架构 §4.2

## 8. 非功能要求
- 加锁事务 P95 ≤50ms；唯一索引冲突返回明确错误码（23000 → SLOT_TAKEN）；reaper 每 5min 一轮。

## 9. AI 开发标准（本模块附加）
- TDD（lj-test-matrix 组合）：R-01 并发双写仅一胜（100 并发压测用例）、R-03 三重防护逐条、R-04 reaper；
- 交叉审查强制（锁是全局正确性根基）；
- 禁止：先建业务实体后补锁（两步非事务）；用 Redis 锁替代 DB 约束做正确性判断。
