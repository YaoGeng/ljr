# B2 时间段占用锁

> 域：B-律师配置 ｜ 架构模块：schedule（机制服务，被 C1/C2/C5 调用） ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：C1（B2C 创建即锁）、C2（发布即 PENDING_PAYMENT）、C5（改期新段） ｜ 下游：I2（TTL/reaper job）、G1（滥用事件）、B1（状态视图） ｜ 技能：P0六件套 + lj-domain-rules + lj-test-matrix

## 1. 职责与边界
- 做：具体场次时刻的占用锁（唯一事实源）；同事务加锁/释放；TTL；滥用防护；reaper 兜底。
- 不做：场次业务状态（trade 域）；锁的业务含义解释（调用方负责）。

## 2. 功能点
- 机制 API：LOCK_SLOT / RELEASE_SLOT / CONFIRM_PAYMENT（PENDING_PAYMENT→LOCKED）/ START_OCCUPY（LOCKED→OCCUPIED）
- 滥用防护：C2B 发布锁绑定支付单 + 10min TTL；每用户对同一律师进行中锁 ≤1、全局 ≤3
- reaper：扫描活跃锁 + 关联实体已终态超阈值 → 释放 + 告警

## 3. 领域模型
slot_locks(
  id bigserial PK,
  lawyer_id bigint NOT NULL, slot_start timestamptz NOT NULL,
  status varchar(20) NOT NULL,  -- PENDING_PAYMENT|LOCKED|OCCUPIED|RELEASED
  ref_type varchar(16) NOT NULL,  -- session|groupbuy|reschedule
  ref_id bigint NOT NULL, initiator_user_id bigint NOT NULL,   -- 发起人（滥用防护计数用）
  payment_order_id bigint NULL, ttl_at timestamptz NULL,
  created_at timestamptz
)
CREATE UNIQUE INDEX ux_slot_active ON slot_locks(lawyer_id, slot_start)
  WHERE status IN ('PENDING_PAYMENT','LOCKED','OCCUPIED');   -- 部分唯一索引=物理防线
CREATE INDEX ix_slot_ttl ON slot_locks(ttl_at) WHERE status = 'PENDING_PAYMENT';
CREATE INDEX ix_slot_user ON slot_locks(initiator_user_id) WHERE status IN ('PENDING_PAYMENT','LOCKED','OCCUPIED');

## 4. 状态机
PENDING_PAYMENT →(支付成功回调, CONFIRM_PAYMENT) LOCKED →(开房, START_OCCUPY) OCCUPIED →(场次终态, RELEASE_SLOT) RELEASED
PENDING_PAYMENT →(TTL 到期/reaper/取消（显式 releaseSlot）) RELEASED
LOCKED →(流标/拒绝/超时/取消, 同事务) RELEASED

## 5. 接口契约（内部机制 API，不暴露 HTTP）
形态：service 方法，首参 uow=调用方业务事务句柄（SqlExecutor，与 I2 registerJob(uow,…) 同形态）——锁写入/状态迁移/领域事件与业务写同 commit/rollback（R-02）。

| 调用 | 入参 | 出参 | 语义
|---|---|---|---
| LOCK_SLOT(uow, {lawyer_id, slot_start, initiator_user_id, ref_type, ref_id, payment_order_id?}) | - | {ok:true, lock_id, status:'PENDING_PAYMENT'|'LOCKED'} 或 {ok:false, reason:'SLOT_TAKEN'|'SLOT_ABUSE_LIMIT'} | 与业务实体同事务执行；payment_order_id 传入⇒PENDING_PAYMENT（ttl_at=now+TTL，同事务注册 SLOT_TTL job），缺省⇒LOCKED（C1 创建即锁/C5 改期新段）；同事务内按 ix_slot_user 计数校验 R-03，超限即拒并发 SlotAbuseDetected
| CONFIRM_PAYMENT(uow, payment_order_id) | - | {ok:true, lock_id, transitioned} 或 {ok:false, reason:'NOT_FOUND'} | 支付回调事务内调用；transitioned=false=回调重放幂等短路（已 LOCKED/OCCUPIED）；NOT_FOUND=无锁行/已 RELEASED（退款后迟到回调）；成功迁移时同步取消 SLOT_TTL job
| RELEASE_SLOT(uow, {ref_type, ref_id, reason}) | - | {ok:true, lock_id} 或 {ok:false, reason:'ALREADY_RELEASED'|'NOT_FOUND'} | 幂等（已释放⇒ALREADY_RELEASED）；与业务终态同事务；PENDING_PAYMENT 释放同步取消 SLOT_TTL job；NOT_FOUND=该 ref 从无锁行（显性化扩展）
| START_OCCUPY(uow, lock_id) | - | {ok:true, lock_id, transitioned} 或 {ok:false, reason:'NOT_FOUND'} | LOCKED→OCCUPIED（开房）；transitioned=false=开房重放幂等短路（已 OCCUPIED，W3 开房 job 重试不抛不留痕）；PENDING_PAYMENT/已 RELEASED ⇒ StateIllegalTransition（拒绝留痕走独立连接）；无行⇒NOT_FOUND

调用方契约（C1/C2/C5 必读）：
- `SLOT_TAKEN`：事务已被 23505 唯一索引冲突（ux_slot_active）污染（PG 语义只能 ROLLBACK）——调用方必须回滚其业务事务。
- `SLOT_ABUSE_LIMIT`：非毒化拒绝（锁行未写入），调用方须显式中止业务写（回滚）；SlotAbuseDetected 已由 B2 经独立连接落 outbox，不随调用方回滚丢失。
- `NOT_FOUND`（RELEASE_SLOT/CONFIRM_PAYMENT/START_OCCUPY）：ref/lock_id 从无锁行或无可处置对象，显性化返回（本表之上的扩展，非静默 ok）。
- `transitioned:false`（CONFIRM_PAYMENT/START_OCCUPY）：重放幂等短路，调用方继续其事务即可，不得视为错误。
- TTL 延长注记：I2 registerJob 同键重注册不刷新 dueAt——延长某锁 TTL 须两步 `cancelJob(SLOT_TTL, ref=slot_lock+lock_id) + registerJob(新 dueAt)`（同事务）。

## 6. 领域事件
- 生产：SlotLocked{lawyer_id, slot_start, ref}；SlotReleased{..., reason}；SlotTtlExpired{...}；SlotAbuseDetected{user_id, lawyer_id, limit}（→G1）。
- 消费：I2 TTL job（到期 PENDING_PAYMENT → 释放）。
- 写入口径：SlotLocked/SlotReleased/SlotTtlExpired 经 recordOutbox 与业务写同事务；**SlotAbuseDetected 经独立连接落 outbox**（拒绝留痕变体，与守卫「非法迁移拒绝留痕走独立连接」先例同构——滥用拒绝路径上调用方事务必然回滚，同事务事件会被一并回滚吞掉）。
- **SlotTtlExpired 与 SlotReleased(reason=TTL_EXPIRED) 为同次释放的双事件（有意设计）**：前者表达 TTL 到期未支付语义，后者是 B1 统一订阅的释放口径（显式/TTL/reaper 释放全经 SlotReleased）——B1 只订阅 SlotReleased，勿按 SlotTtlExpired 重复计数。

## 7. 业务规则
- R-01 同一律师同一时间段只能存在一个有效场次（部分唯一索引兜底，DB 是唯一事实源；Redis 前置锁仅性能优化）｜PRD §6.5、架构 §4.2
- R-02 锁状态迁移与业务状态迁移同一 DB 事务（流标/拒绝/超时/取消同步释放；领域事件只通知下游）｜架构 §4.2
- R-03 C2B 滥用防护：PENDING_PAYMENT 纳入唯一索引 + 10min TTL 自动释放；每用户对同律师进行中锁 ≤1、全局 ≤3（同事务内按 ix_slot_user 计数，超限返 SLOT_ABUSE_LIMIT + SlotAbuseDetected 事件）｜架构 §4.2
- R-04 reaper：活跃锁 + 关联实体终态超阈值（15min）强制释放并告警（锁泄漏兜底）。扫描说明：PENDING_PAYMENT 走 ttl_at 部分索引；LOCKED/OCCUPIED 为全量扫描（V1 活跃锁 ≤万级，每 5min 一轮预算可接受；量级增长后补 created_at 部分索引）。终态判定经 TerminalStateProvider 注册表（禁跨域 join）：`isTerminal(ref_id)` 单实体 + 可选 `isTerminalBatch(ref_ids)` 批量形态（reaper 每轮对每 ref_type 至多一次批量调用，防逐行 N+1）——**量级触发线**：provider 未实现批量而走逐行回退时，活跃锁上万即成 N+1 扫描，provider 落位（C1/C2/C5）时应实现批量形态；缺 provider=跳过该 ref_type（漏放方向，宁漏不误杀），跳过/异常行数经 reaper 结果计数暴露（skipped_no_provider / skipped_errored，落 schedule_job_log）｜架构 §4.2

## 8. 非功能要求
- 加锁事务 P95 ≤50ms；唯一索引冲突返回明确错误码（23505 + 约束名精确匹配 ux_slot_active → SLOT_TAKEN）；reaper 每 5min 一轮。

## 9. AI 开发标准（本模块附加）
- TDD（lj-test-matrix 组合）：R-01 并发双写仅一胜（100 并发压测用例）、R-03 三重防护逐条、R-04 reaper；
- 交叉审查强制（锁是全局正确性根基）；
- 禁止：先建业务实体后补锁（两步非事务）；用 Redis 锁替代 DB 约束做正确性判断。
