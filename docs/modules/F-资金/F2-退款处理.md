# F2 退款处理

> 域：F-资金 ｜ 架构模块：payment ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：C1（流标）、C4（拒绝/超时/转化 24h 窗）、D1（无人到场）、D4（取消矩阵）、D6（1对1 三档/补差退）、C5（改期失败兜底） ｜ 下游：F1（退款指令）、I1（通知）、H4 ｜ 技能：P0六件套 + lj-payment-invariants

## 1. 职责与边界
- 做：退款原因分类受理→指令下发→状态跟踪→通知；批量退款；退款还原（现金+积分）。
- 不做：退款规则判定（各发起方）；通道执行（F1）。

## 2. 功能点
- 原因枚举：GROUP_FAIL|LAWYER_REJECT|TIMEOUT|CONVERT_WINDOW|NO_SHOW_ALL|CANCEL_RULE|OOO_CANCEL|OOO_TIMEOUT|SETTLE_REFUND
- 批量（流标全员/转化窗多人）；用户侧退款状态查询
- 金额规则：按原支付拆分还原（cash 原路、points 还原积分）

## 3. 领域模型
refunds(
  id bigserial PK, payment_order_id bigint NOT NULL,
  cash_amount numeric(12,2) NOT NULL DEFAULT 0, points_amount int NOT NULL DEFAULT 0,
  reason varchar(32) NOT NULL, status varchar(16) NOT NULL,  -- REQUESTED|PROCESSING|DONE|FAILED
  idempotency_key varchar(64) NOT NULL UNIQUE, requested_at, done_at
)

## 4. 关键流程
受理（幂等键=原因+实体）→ F1 /pay/refund → 状态跟踪（回调推进）→ I1 通知 → H4 指标。失败重试 3 次后工单。

## 5. 接口契约
| 内部 | ISSUE_REFUND | {order_id, cash, points, reason, idempotency_key} | {refund} | 409 DUP | 幂等键
| GET | /refunds/mine | - | 状态列表 | - | 否

## 6. 领域事件
- 生产：RefundCompleted{refund_id, order_id, amounts}（→C3 状态推进、I1、H4）；RefundFailed（→H3 工单）。
- 消费：各发起方退款事件（SessionFailed/LawyerRejected/SessionCancelled/...）。

## 7. 业务规则
- R-01 原路退回 1-3 工作日 ｜PRD §8.7
- R-02 未成团自动退款（流标/拒绝/超时全额）｜PRD §7.1.4/§8.1
- R-03 积分抵扣部分退款还原为积分（不退现金）⚠04§8-1 ｜本文档口径（与 F1 R-03 一致）
- R-04 幂等：同一原因+实体仅一笔 ｜架构 §4.4

## 8. 非功能要求
- 批量退款（100 人）≤2min；失败重试+工单兜底；用户可见状态实时。

## 9. AI 开发标准（本模块附加）
- 交叉审查强制；
- TDD：幂等、批量部分失败（可重入）、积分还原不退现金额、金额守恒（退款总额≤支付额）；
- 禁止：金额 float；绕过幂等键补发退款。
