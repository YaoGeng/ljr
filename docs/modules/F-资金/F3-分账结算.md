# F3 分账结算（含违约金/保证金/HOLD）

> 域：F-资金 ｜ 架构模块：settlement + payment ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：D1/D3/D4（履约完成/判定/违约）、A3b（进件状态）、H3（纠纷挂起/释放）、B3（1对1 结算价） ｜ 下游：F1（分账/扣划指令）、F4（备付台账）、H4 ｜ 技能：P0六件套 + lj-payment-invariants（交叉审查强制）

## 1. 职责与边界
- 做：分账触发状态机（唯一解冻节点）；分账构成计算（律所+平台费+缺席分成）；违约扣减顺序；HOLD 管理。
- 不做：退款（F2）；权益台账（F4）；进件状态（A3b）。

## 2. 功能点
- HOLD：FINISHED 后 24h 或存在未结纠纷工单则挂起；释放后 SETTLED
- 构成：律师费（70% 缺席分成/正常服务费）→ 律所对公；平台服务费（fee_versions 版本化，前期 0%）；30% 缺席分成 → 平台分账接收账户（备付，F4 台账）
- 违约扣减：待结算余额优先 → 保证金专户补足（F1 /pay/deduct）
- 进件前置：firm_merchants 非 ACTIVE 拒绝分账并挂起（SUSPENDED 事件消费）

## 3. 领域模型
settlements(
  id bigserial PK, ref_type varchar(16) NOT NULL, ref_id bigint NOT NULL,  -- session|one_on_one
  lawyer_id, firm_id,
  gross numeric(12,2) NOT NULL, penalty numeric(12,2) NOT NULL DEFAULT 0,
  platform_fee numeric(12,2) NOT NULL DEFAULT 0, fee_version_id bigint NOT NULL,
  net numeric(12,2) NOT NULL,
  escrow_status varchar(16), deduction_detail jsonb,   -- {from: settlement|deposit, items[]}
  status varchar(16) NOT NULL,                 -- PENDING|HOLD|READY|SETTLED|SUSPENDED
  hold_reason varchar(32), created_at, settled_at,
  UNIQUE(ref_type, ref_id)
)
注：场次结算 ref=(session, id)；1对1 结算 ref=(one_on_one, order_id)，消费 OneOnOneSettled{order_id, gross, net} 载荷；1对1 平台服务费同 fee_versions 口径。
fee_versions(id PK, rate numeric(5,4) NOT NULL, effective_at)  -- 0.0000 起，逐步 0.05-0.10

## 4. 分账触发状态机
FINISHED（场次/1对1）→ PENDING → HOLD(24h 或 open_tickets>0) → READY →（进件 ACTIVE 校验）→ SETTLED
SUSPENDED：进件非 ACTIVE → 挂起待进件恢复（事件驱动重试）。
守卫：唯一解冻分账节点=READY→SETTLED；成团仅续冻（F1 续冻指令）。

## 6. 领域事件
- 生产：SplitSettled{session_id, net, fee, splits}；SettlementHeld{session_id, reason}；SettlementReleased{...}。
- 消费：RoomClosed/OneOnOneSettled（进 PENDING，含 1对1）；AttendanceAdjudicated（缺席分成计算）；SessionCancelled（APPLY_PENALTY 违约扣减，金额按 C3 快照基数）；FirmMerchantActivated/Suspended（前置/挂起）；TicketResolved（HOLD 释放）；ScheduleJobFired(SETTLE_HOLD_RELEASE)（24h 到期自动 READY）。

## 7. 业务规则
- R-01 唯一解冻分账节点=履约完成+HOLD 过/释放；成团仅续冻 ｜架构 §4.4
- R-02 HOLD 24h；未结纠纷挂起该场结算 ｜架构 §4.4
- R-03 缺席费用 70% 律师 + 30% 平台分账接收账户（备付金定性 ⚠）｜PRD §8.5
- R-04 违约扣减顺序：待结算余额 → 保证金专户；不足挂欠款+暂停接单（D4/G1 协同）｜架构 §4.4
- R-05 违约金全额按支付占比补偿用户，平台不抽佣 ｜PRD §8.6
- R-06 平台服务费版本化（0% 起步）｜PRD §9.5
- R-07 进件非 ACTIVE 不分账 ｜A3b R-01

## 8. 非功能要求
- 结算 job 幂等（重复触发一笔）；对账钩子（F1 SplitLedger 核对）；HOLD 超时未处置告警。

## 9. AI 开发标准（本模块附加）
- 交叉审查强制（最高资损面）；
- TDD：触发状态机全迁移、HOLD 边界（24h/工单开闭）、70/30 与占比计算、扣减顺序两档、进件挂起恢复；
- 禁止：跳过 HOLD 直分；金额 float；违约金抽佣（平台不抽是硬规则）。
