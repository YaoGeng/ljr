# I2 调度中心

> 域：I-平台支撑 ｜ 架构模块：调度域（schedule_jobs 事实源） ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：全域（业务状态迁移同事务写 job） ｜ 下游：各执行模块（job 触发） ｜ 技能：P0六件套 + lj-domain-rules

## 1. 职责与边界
- 做：schedule_jobs 到期任务表事实源；多节点 SKIP LOCKED 抢占（10-15s 周期）；执行器幂等回查；job 全集注册；准点保障与告警；log 可重放。
- 不做：业务逻辑（执行器在各模块）。

## 2. 功能点
- job 类型全集（26 种）：REMIND_24H/1H/10MIN/1MIN、ENROLL_DEADLINE、ROOM_OPEN、GRACE_END、REMIND_GRACE_END、ABSENT_15M、NO_SHOW_CLOSE、C2B_CONFIRM_TIMEOUT、RESCHEDULE_CONFIRM_TIMEOUT、OOO_ACCEPT_TIMEOUT、OOO_SETTLE_DEFAULT、DIFF_PAY_TIMEOUT、COMPENSATION_DISPATCH、SETTLE_HOLD_RELEASE、SLOT_REAPER、SLOT_TTL、POINTS_EXPIRE、RETENTION_PURGE、COLD_ARCHIVE、FIRM_REVERIFY、RULE_EFFECTIVE、RISK_PATROL、RESERVE_RECONCILE（计数注记：历史「21/25 种」系旧稿枚举数；代码注册表含 R2 追加 RULE_EFFECTIVE、M1-W4 RISK_PATROL、M2-W1 COLD_ARCHIVE/REMIND_GRACE_END 与 M2-W2 T6 RESERVE_RECONCILE（F4 日终备付对平，第 26 项）=26，以本行枚举与 §4 对照表并集为准——见 scheduler.catalog.ts 头注 ⚠计数差异说明）
- 排除声明：RESTRICTION_EXPIRE 不建 job（G1 限制令采用惰性失效：查询时比对 until，见 G1 §3）；其余调度需求一律入全集
- 与业务同事务写/作废 job（发件箱模式同理）
- 延迟消息仅 1min/10min 级提醒优化（非事实源）

## 3. 领域模型
schedule_jobs(
  id bigserial PK, job_type varchar(32) NOT NULL, ref_type varchar(16), ref_id bigint,
  due_at timestamptz NOT NULL, status varchar(12) NOT NULL,  -- PENDING|RUNNING|DONE|CANCELLED|FAILED
  version int NOT NULL DEFAULT 1,             -- 业务作废靠 version 比对
  retry_count smallint DEFAULT 0, created_at, fired_at
)
CREATE INDEX ix_jobs_due ON schedule_jobs(due_at) WHERE status = 'PENDING';
schedule_job_log(id PK, job_id, job_type, ref, fired_at, result, duration_ms)
抢占：SELECT ... FOR UPDATE SKIP LOCKED LIMIT batch（多节点安全）。

## 4. 关键流程
执行器：抢占 → 回查业务当前状态（version/状态守卫）→ 过期则 CANCELLED 无操作 → 执行 → DONE；异常重试（退避，3 次后 FAILED+告警）。
开房类 job（ROOM_OPEN）：独立高优先级队列，扫描周期 ≤5s（其他 10-15s）；延迟 >30s 电话告警。

**job 全集对照表**（生产模块 ↔ 执行器 ↔ 回查锚点，供程序化一致性检查）：

| job 类型 | 生产方 | 执行器 | 回查锚点 |
|---|---|---|---|
| REMIND_*×4 / ENROLL_DEADLINE | C3（成团）/C1（创建） | D2 / C1（流标） | 场次状态是否仍有效 |
| ROOM_OPEN / GRACE_END / REMIND_GRACE_END / ABSENT_15M / NO_SHOW_CLOSE | D1 | D1 / D3（REMIND_GRACE_END=D2 房间内提醒；GRACE_END W1 执行器=D1 发事件即止，判定=D3=W2 事件消费——M2-W1 附录 A.2 裁决；ABSENT_15M/NO_SHOW_CLOSE=D1 开房成功同事务预写 due=grace_end+15min、D3 执行器 M2-W2 装配——**recheck 实现锚**：ABSENT_15M=room 非 CANCELLED 且名册存在未判定行（⚠W2-10 判定与房间生命周期正交）、NO_SHOW_CLOSE=room 仍 OPEN） | room 状态与开房结果（实现细化=M2-W2 T2，目录措辞以本行注记为准） |
| C2B_CONFIRM_TIMEOUT | C2（REACHED） | C2（①期超时自动拒档已落=trade/C2，task-5-report §5；显式拒绝档=C4 M2 接管） | group_buy 状态 |
| RESCHEDULE_CONFIRM_TIMEOUT | C5（申请） | C5 | reschedule_requests 状态 |
| OOO_ACCEPT_TIMEOUT / OOO_SETTLE_DEFAULT / DIFF_PAY_TIMEOUT | D6 | D6（**executor 已装配=M2-W3 T2**：PAID 同事务预写 accept 锅（due=accept_deadline=paid_at+N）/FINISHED 预写实结默认（due=finished_at+30min，D9 配置化）/DIFF_PENDING 预写补差超时（due=+15min）；N/30min/15min=LJR_FULFILLMENT_OOO_* env 键） | one_on_one_orders 状态 |
| COMPENSATION_DISPATCH | C6 | F4 | pricing_histories 补偿发放状态（**M2-W2 T6 裁定**：保留在册不装配——补偿直发真链=M1-W3 T9 官方形态，本 job 无预写路径零噪音；24h SLA 把关=RISK_PATROL ⑤类对照 V44 comp_snapshots 快照（#39 收口）） |
| SETTLE_HOLD_RELEASE | F3（进 HOLD） | F3（24h 到期→READY） | settlements.hold 状态与工单 |
| SLOT_REAPER / SLOT_TTL | B2 | B2 | slot_locks 与实体终态 |
| POINTS_EXPIRE | F4 | F4 | points_txns.expires_at |
| RETENTION_PURGE | I3 | I3 | artifacts.retention_until |
| COLD_ARCHIVE | D5（messages 冷存扫描属 fulfillment 自持，写经 I3 PUT_ARTIFACT 统一入口；主库清理限本域表） | D5（周期 job 自投，日扫） | messages 冷存水位（last_archived_created_at，M2-W1 T3 落位） |
| FIRM_REVERIFY | A3b（进件生效时） | A3b | firm_merchants.reverify_due |
| RISK_PATROL | H4（main.ts 引导 + 执行器自投下一周期，分钟级） | H4（PatrolService.runOnce：五类资损不变量检测→违例台账+告警） | patrol_runs 最近一轮状态（M1-W4 T1 落位，架构 §7.2） |

**FAILED 处置**：job 重试退避 3 次后置 FAILED + 告警工单（H3 dead_letter）；FAILED 不自动重试，由运维经 log 重放（同 job_id 重新入队，幂等回查保证安全）；告警收敛：同类型 FAILED 5min 内去重。

## 5. 接口契约
| 内部 | REGISTER_JOB / CANCEL_JOB | 与业务同事务 | - | - | 幂等键=type+ref
| GET | /admin/scheduler/jobs?status=&type= | - | 运维视图 | - | 否

## 6. 领域事件
- 生产：ScheduleJobFired{job_id, type, ref}（→执行模块）。
- 消费：无。

## 7. 业务规则
- R-01 DB 到期任务表=事实源；延迟消息仅优化 ｜架构 §4.5
- R-02 执行前回查（人工先到则幂等无操作）｜架构 §4.5
- R-03 开房准点 + >30s 电话告警 ｜架构 §4.5/§7.2
- R-04 全部调度事件落 log 可重放 ｜架构 §4.5

## 8. 非功能要求
- 扫描周期：ROOM_OPEN ≤5s，其余 10-15s；抢占吞吐 ≥500 job/s；多节点无重复执行（SKIP LOCKED 测试）。

## 9. AI 开发标准（本模块附加）
- TDD：抢占并发（两节点同 job 恰一执行）、回查幂等、作废生效、开房优先级、重试退避；
- 禁止：依赖 RocketMQ 延迟消息做正确性（仅提醒优化）。
