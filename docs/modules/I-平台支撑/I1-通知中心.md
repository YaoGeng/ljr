# I1 通知中心

> 域：I-平台支撑 ｜ 架构模块：notify ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：全域通知事件 ｜ 下游：推送/SMS/站内信通道、用户端 ｜ 技能：P0六件套

## 1. 职责与边界
- 做：通知统一编排（推送/SMS/站内信）；模板管理（含 PRD §8.2 三档改价话术）；触达记录；验证码通道（A1）。
- 不做：业务触发逻辑（各域发事件）；房间内消息（D5）。

## 2. 功能点
- 通道：App 推送（厂商通道聚合）、SMS、站内信
- 模板：code 化（PRICE_UP_LOCKED/PRICE_DOWN_COMP/PRICE_DOWN_BIG/...），参数渲染，三档改价话术与 PRD 文案一致
- 触达记录与重试；用户通知偏好（可关非关键类）

## 3. 领域模型
notifications(id PK, user_id, channel varchar(8), template_code varchar(32), params jsonb,
  status varchar(12),  -- QUEUED|SENT|FAILED|SKIPPED(prefs)
  idempotency_key varchar(64) UNIQUE, sent_at, created_at)
notification_templates(code PK, channel, content text, version int)

## 4. 关键流程
事件消费 → 模板渲染 → 偏好过滤 → 通道下发 → 回执更新；失败重试 3 次。

## 5. 接口契约
| 内部 | DISPATCH_NOTIFY | {user_id, template_code, params, idempotency_key} | - | - | 幂等键
| GET | /notifications/mine | - | 站内信列表 | - | 否
| GET/PUT | /notification-prefs | - | 偏好 | - | 否

## 6. 领域事件
- 生产：NotificationDispatched{id, template_code, status}（→H4 触达率）。
- 消费：全域通知类事件（ReminderDispatched/PriceChangeApproved/...）。

## 7. 业务规则
- R-01 三档改价话术按 PRD §8.2 文案 ｜PRD §8.2
- R-02 验证码限频承接（A1 规则，本模块执行计数）｜A1 R-01
- R-03 幂等：同 idempotency_key 一次触达 ｜架构 §2.1

## 8. 非功能要求
- 通知发送 P95 ≤2s（队列）；触达率统计日报。

## 9. AI 开发标准（本模块附加）
- TDD：模板渲染（三档话术与 PRD 文案全等断言）、幂等、偏好过滤；
- 禁止：话术文案硬编码业务模块（模板中心统一）。
