# A2 实名认证与同意管理

> 域：A-身份与账号 ｜ 架构模块：identity ｜ V1 ｜ P0 ｜ 阶段：①
> 上游：A1 ｜ 下游：C3/F1（实名闸口）、D5/I3（撤回删除执行）、H9（监督） ｜ 技能：P0六件套 + lj-data-security + lj-compliance-guards

## 1. 职责与边界
- 做：实名提交与核验（姓名+身份证，通道 ⚠CTID/三要素）；consents 全 scope 管理（realname / training / recording）；支付流程内训练数据独立授权页；设置中心撤回入口；实名单独同意记录；受控解密（审批+双人复核）。
- 不做：撤回后的语料删除执行（D5/I3 执行，本模块只发事件）；支付拦截逻辑（C3 调用查询接口）。

## 2. 功能点
- 实名提交 → 核验通道 → verified（默认仅存核验结果 + 凭据摘要）
- 独立授权页（首次成团/支付流程内）：training scope，可拒绝（拒绝不影响拼单/房间功能，仅该房间消息不进训练语料）
- 设置中心：授权状态查询与撤回（policy_version 记录）
- 受控解密工作流：合规审批 → 双人复核 → 临时解密（审计留痕）

## 3. 领域模型
real_name_infos(
  id bigserial PK, user_id bigint UNIQUE NOT NULL,
  verify_provider varchar(32) NOT NULL,        -- CTID|CARRIER3 等（⚠选型）
  verify_token_digest char(64) NOT NULL,       -- 凭据摘要（不存原文）
  name_enc bytea NULL, id_no_enc bytea NULL,   -- 密文仅纠纷处理目的留存（KMS）
  verified_at timestamptz NOT NULL
)
consents(
  id bigserial PK, user_id bigint NOT NULL, scope varchar(16) NOT NULL,  -- realname|training|recording
  status varchar(16) NOT NULL,                -- GRANTED|REVOKED
  policy_version varchar(16) NOT NULL, granted_at timestamptz, revoked_at timestamptz NULL
)
CREATE UNIQUE INDEX ux_consent_active ON consents(user_id, scope, policy_version) WHERE status = 'GRANTED';
-- 活跃态唯一：同版本重复 GRANTED 返回现值（幂等）；REVOKED 后可再次 GRANTED（新行）
注：房间级 training 授权映射由 D5 的 consent_records(ref_type IN ('recording','training_room')) 承载；本模块事件 TrainingConsentGranted 载荷带 room_ids，D5 据此落表。

## 4. 状态机
consent: ABSENT → GRANTED → REVOKED（可再次 GRANTED 新 policy_version）。
- 跨版本授权：新 policy_version=插新 GRANTED 行（旧行不动）；撤回仅作用于最新活跃行；状态查询「当前同意」取最新 GRANTED 行（无活跃授权才回退展示最新 REVOKED 行）——实现口径回写（文档原未定义跨版本撤销语义，不发明）。
realname: NONE → PENDING(核验中) → VERIFIED / FAILED(可重提)。

## 5. 接口契约
| 方法 | 路径 | 入参 | 出参 | 错误码 | 幂等
|---|---|---|---|---|---
| POST | /realname | {name, id_no} | {status} | 400 INVALID_ID | 幂等键=user
| GET  | /realname/status | - | {status, verified_at} | - | 否
| POST | /consents/training | {policy_version, accept} | {status} | 409 VERSION_MISMATCH | 幂等键=user+policy_version
| POST | /consents/training/revoke | - | {status, revoked_at} | - | 否
| GET  | /consents/training | - | {status, policy_version, granted_at?, revoked_at?}（当前同意视图） | - | 否
| GET  | /admin/realname/decrypt | {user_id, reason, approval_id} | {name, id_no}（双人复核） | 403 NOT_APPROVED | 否

## 6. 领域事件
- 生产：RealNameVerified{user_id}；TrainingConsentGranted{user_id, policy_version, room_ids?}；TrainingConsentRevoked{user_id, revoked_at}。
- 消费：无（发起方）。

## 7. 业务规则
- R-01 支付前实名闸口：C3/F1 下单前查 realname.status=VERIFIED ｜PRD §7.1.1、架构 §4.4
- R-02 训练授权独立同意：不并入用户协议一揽子授权；拒绝不降级产品功能 ｜架构 §5.2 合规 R3
- R-03 撤回链路：TrainingConsentRevoked → D5/I3 按 source_msg_id 反查物理删除未训练样本；已训练模型处置 ⚠04§8-6 ｜架构 §5.2
- R-04 密文最小化：默认仅存摘要+凭据；密文解密需 H9 审批+双人复核 ｜架构 §5.2 合规 R6
- R-05 实名信息不对外展示 ｜PRD §7.1.1

## 8. 非功能要求
- 授权页在支付流程内一步完成、可记忆（同 policy_version 不重复弹）；核验通道 P95 ≤3s；解密操作全审计（H9）。

## 9. AI 开发标准（本模块附加）
