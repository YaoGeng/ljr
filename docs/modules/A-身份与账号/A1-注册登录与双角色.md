# A1 注册登录与双角色

> 域：A-身份与账号 ｜ 架构模块：identity（schema: identity） ｜ 版本：V1 ｜ 优先级：P0 ｜ 施工阶段：①
> 上游依赖：I1（验证码下发） ｜ 下游被依赖：全部 App 端模块（登录态） ｜ 必载技能：P0六件套 + lj-domain-rules + lj-data-security

## 1. 职责与边界
- 做：手机号验证码注册登录/登出、JWT 双 token 签发与刷新、双角色切换（重签 claims）、账号状态管理、注册环节年龄声明。
- 不做：实名（A2）、角色业务数据（各域自理）、权限细粒度（网关 RBAC）。
- 边界纪律：只写 identity schema；角色数据隔离由客户端角色路由 + 接口级 claims 校验实现，不在本模块复制业务数据。

## 2. 功能点
- 验证码登录（手机号+SMS code，60s 有效，1 分钟 1 条/1 小时 5 条/1 天 10 条限频）
- access_token(2h) + refresh_token(14d) 刷新与吊销
- 角色切换 POST /auth/switch-role（user<->lawyer，重签 claims）
- 年龄声明（注册协议内勾选"已满 14 周岁；不满 14 需监护人同意"——架构 §6 未成年人保护）
- 账号状态：ACTIVE / BANNED / DELETING（A4）

## 3. 领域模型（DDL 级）
users(
  id            bigserial PRIMARY KEY,
  phone_enc     bytea NOT NULL,               -- 列加密（KMS 信封）
  phone_blind_idx char(64) NOT NULL,          -- HMAC-SHA256(phone, pepper) 盲索引
  status        varchar(16) NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE|BANNED|DELETING
  age_declared  boolean NOT NULL DEFAULT false,
  created_at    timestamptz NOT NULL DEFAULT now()
)
CREATE UNIQUE INDEX ux_users_phone ON users(phone_blind_idx);
user_roles(user_id bigint REFERENCES users(id), role varchar(8) CHECK (role IN ('user','lawyer')), PRIMARY KEY(user_id, role));
refresh_tokens(id bigserial PK, user_id, token_hash char(64), expires_at timestamptz, revoked_at timestamptz NULL);

## 4. 状态机与关键流程
- 登录：phone(+code 校验) → 盲索引查 users → 不存在则建号(user role) → 签发双 token。
- 切换角色：校验 user_roles 含目标角色 → 重签 access_token（claims.role）→ 客户端重载角色路由。
- 律师角色仅 A3a 审核通过后由审核动作授予（本模块不授）。

## 5. 接口契约
| 方法 | 路径 | 入参 | 出参 | 错误码 | 幂等
|---|---|---|---|---|---
| POST | /auth/sms | {phone} | {ttl:60} | 429 RATE_LIMITED | 否(限频)
| POST | /auth/verify | {phone, code} | {access_token, refresh_token, roles} | 401 CODE_INVALID | 否
| POST | /auth/refresh | {refresh_token} | {access_token} | 401 REFRESH_EXPIRED | 否
| POST | /auth/switch-role | {target_role} | {access_token} | 403 ROLE_NOT_HELD | 否
| GET  | /me | - | {id, roles, status, phone_masked} | 401 | 否

## 6. 领域事件
- 生产：UserRegistered{user_id, utm?}（→H8 归因、H4）。
- 消费：LawyerAuditPassed（授予 lawyer role，来自 A3a）；AccountDeletionExecuted（置 DELETING，来自 A4）。

## 7. 业务规则
- R-01 验证码限频：同号 60s/1 条、1h/5 条、1d/10 条（Redis 计数器）｜溯源 PRD §7.1.1、架构 §6
- R-02 双角色同账号：lawyer 账号默认具备 user 身份；切换不产生新账号 ｜PRD §3
- R-03 界面数据隔离：接口层 claims.role 校验（律师端接口拒 user token）｜PRD §3、架构 §6
- R-04 年龄声明未勾选不得完成注册 ｜架构 §6

## 8. 非功能要求
- 登录 P95 ≤500ms（不含 SMS 到达）；短信失败率告警；refresh 吊销即时生效（Redis 黑名单）。

## 9. AI 开发标准（本模块附加）
- TDD 先行用例：R-01 限频四档、R-03 越权访问、盲索引唯一冲突；
- 禁止：明文手机号落库/落日志（lj-data-security）；token 写死；角色提升逻辑放在本模块（只消费事件）。
