# H3 纠纷工单与退款审核

> 域：H-运营后台 ｜ 架构模块：ops ｜ V1 ｜ P1 ｜ 阶段：②（C6 ①期人工兜底用）
> 上游：D4（<24h 取消审批）、C6（改价审批）、F1（对账差异/死信）、用户申诉 ｜ 下游：F2/F3（审批结果执行）、C6、H4 ｜ 技能：P0六件套 + lj-payment-invariants

## 1. 职责与边界
- 做：工单分类/SLA/流转；退款审批（律师<24h 取消等）；改价超频/<24h 审批；结算 HOLD 释放；死信工单。
- 不做：规则判定（发起方）；执行（F2/F3/C6 回调）。

## 2. 功能点
- 工单类型：dispute/refund_review/price_change/cancel_lt24h/reconciliation/dead_letter/export_recording
- SLA：对账差异 24h（硬）；其余 48h（软）
- 审批动作 → 回调发起方模块（幂等）

## 3. 领域模型
tickets(
  id bigserial PK, category varchar(24) NOT NULL, ref_type varchar(16), ref_id bigint,
  title, detail text, status varchar(16) NOT NULL,  -- OPEN|PROCESSING|RESOLVED|REJECTED
  priority smallint, sla_due timestamptz, assignee_id bigint, created_at, resolved_at
)
ticket_actions(id PK, ticket_id, action, operator_id, payload jsonb, created_at)   -- 审计

## 4. 关键流程
创建（事件/人工）→ 分派 → 处理（审批动作带 payload）→ 回调发起方 → RESOLVED；SLA 超时升级告警。

## 5. 接口契约
| GET/POST | /admin/tickets[/{id}] | 筛选/创建 | - | - | 幂等键=category+ref
| POST | /admin/tickets/{id}/resolve | {action_payload} | {status} | 409 CLOSED | 幂等键=ticket
审批回调（对 C6/D4）：POST /pricing/change/{id}/approve、/cancellations/{id}/approve。

## 6. 领域事件
- 生产：TicketCreated/Resolved（→F3 HOLD 释放、C6/D4 审批结果、H4）。
- 消费：ReconciliationDiffFound、RefundFailed、死信事件。

## 7. 业务规则
- R-01 纠纷处理工单 ｜PRD §7.3
- R-02 退款审核（律师<24h 取消）｜PRD §8.6
- R-03 对账差异 SLA 24h ｜架构 §4.4
- R-04 存在未结纠纷 → 该场结算 HOLD ｜架构 §4.4（F3 联动）

## 8. 非功能要求
- SLA 超时率指标（H4）；审批回调幂等。

## 9. AI 开发标准（本模块附加）
- TDD：SLA 计算、审批回调幂等、状态流转；
- 禁止：审批逻辑内嵌资损规则（只透传决策）。
