# H5 风控与敏感词管理

> 域：H-运营后台 ｜ 架构模块：风控 + ops ｜ V1 ｜ P0 ｜ 阶段：①词库/②人审闭环
> 上游：D5（同步风控调用）、E1（硬拦词表共用） ｜ 下游：H3（人审工单）、G1（违规信用） ｜ 技能：P0六件套 + lj-compliance-guards

## 1. 职责与边界
- 做：双词库管理（违法信息类型+行业违规话术）；机审分级处置（拦截/人审/标记）；人审工单闭环；词库热更新（走 H7 版本化）。
- 不做：消息链路（D5 调用本模块判定）；规则公示（H7）。

## 2. 功能点
- 双词库：illegal_content（涉政/色情/暴恐/诈骗）；legal_industry（承诺结果/包赢/私下交易/加微信/个人收款）
- 分级：词级配置 action（BLOCK→同步拦截；REVIEW→放行+人审队列；MARK→标记）
- 同步判定 API（D5 发送路径，P95 ≤50ms）；二次模型复核（MQ 异步，命中补拦截）
- 定期巡查任务（历史消息抽样复核）

## 3. 领域模型
sensitive_words(id PK, dict_type varchar(20) NOT NULL, word varchar(64) NOT NULL,
  action varchar(8) NOT NULL,  -- BLOCK|REVIEW|MARK
  rule_version int NOT NULL, enabled bool, UNIQUE(dict_type, word))
risk_records(id PK, message_id, dict_type, word_hits jsonb, action, reviewed_by, reviewed_at)
词库缓存：Redis 全量 + 版本号（更新 1min 内生效）。

## 4. 关键流程
D5 send → 判定（词库 AC 自动机/DFA）→ BLOCK 拒发 / REVIEW 放行+入队 / MARK 放行；MQ 二次复核（模型）→ 补拦截+工单。
人审：队列 → 处置（确认拦截误放→补拦截；误拦→放行+用户通知）→ 审计。

## 5. 接口契约
| 内部同步 | CHECK_RISK | {conversation_id, content} | {action, hits} ≤50ms | - | 否（无副作用判定+REVIEW 记录）
| GET/PUT | /admin/risk/dictionaries | 词库管理 | - | 400 DUP_WORD | 幂等键=dict+base_version
| GET | /admin/risk/queue | - | 人审队列 | - | 否
| POST | /admin/risk/records/{id}/review | {verdict} | - | 409 DONE | 幂等键=record

## 6. 领域事件
- 生产：RiskBlocked{message_id, hits}（→H3 工单/G1 规则）；DictionaryUpdated{rule_version}（→D5/E1 缓存刷新）。
- 消费：MessageSent（二次复核）。

## 7. 业务规则
- R-01 双词库+分级处置+人审闭环+定期巡查 ｜PRD §7.2.8、架构 §6 内容风控四件套
- R-02 所有文本会话统一链路（房间/私聊/1对1）｜架构 §6
- R-03 词库热更新走 H7 版本化（公示豁免：词库属风控配置非用户规则 ⚠实现约定：版本化但不公示）
- R-04 语音/视频 V1 事后审核+元数据风控；实时音频审核 V2 边界 ｜架构 §6
- R-05 禁止引导私下交易/加微信/个人收款（专项词表）｜PRD §14.2

## 8. 非功能要求
- 判定 P95 ≤50ms（D5 预算内）；词库更新 1min 生效；AC 自动机内存 ≤50MB。

## 9. AI 开发标准（本模块附加）
- TDD：三动作分级、词库热更新生效、同步异步双路（异步补拦截）、巡查抽样；
- 禁止：判定逻辑外溢到 D5（D5 只调 API）；词库明文进 git（运营后台配置）。
