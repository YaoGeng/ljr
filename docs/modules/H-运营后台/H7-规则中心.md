# H7 规则中心（含房间须知内容块）

> 域：H-运营后台 ｜ 架构模块：pricing/credit + ops ｜ V1 ｜ P1 ｜ 阶段：①
> 上游：C6/G1/D4/H5（规则消费方） ｜ 下游：I1（公示通知）、D5（须知内容）、App 规则页 ｜ 技能：P0六件套 + lj-domain-rules

## 1. 职责与边界
- 做：rule_definitions 通用规则版本化（改价/信用/取消缺席/免责话术/房间须知内容块）；变更状态机（草案→公示 ≥7 日→生效）；行为时快照查询；App 规则页接口。
- 不做：规则执行（各消费方按快照执行）。

## 2. 功能点
- 规则域：price_change / credit / cancellation / disclaimer / room_notice
- 变更流：DRAFT → PUBLISHED(公示) → EFFECTIVE（≥7 日后）
- 快照查询：按行为时刻取当时生效版本
- 房间须知内容块：可配置文案（含"法律意见由执业律师作出、平台提供信息技术撮合"披露），D5 进房拉取

## 3. 领域模型
rule_definitions(
  id bigserial PK, rule_key varchar(32) NOT NULL, version int NOT NULL,
  content jsonb NOT NULL, effective_at timestamptz, publish_status varchar(12) NOT NULL,
  published_at timestamptz, UNIQUE(rule_key, version)
)
查询：SELECT * WHERE rule_key=? AND effective_at <= now() ORDER BY version DESC LIMIT 1（行为时快照传 ts 参数）。

## 4. 关键流程
编辑 → DRAFT → 提交公示（PUBLISHED，I1 通知+App 规则页展示"即将生效"）→ 7 日后自动 EFFECTIVE → 消费方按行为时刻取版本。
重大规则公开征求意见（公示期内反馈入口）。

## 5. 接口契约
| GET/POST | /admin/rules[/{key}] | 管理/提交公示 | - | 409 PUBLISHING | 幂等键=key+version
| GET | /rules/current?key= | App 现行版本 | - | 否
| GET | /rules/snapshot?key=&at= | 行为时快照（内部） | - | 否
| GET | /rooms/notice-content?key=room_notice | 须知内容（D5 消费） | - | 否

## 6. 领域事件
- 生产：RulePublished{rule_key, version, effective_at}（→I1 公示通知、D5 须知刷新、消费方缓存失效）。

## 7. 业务规则
- R-01 规则版本化+公示 ≥7 日+行为时快照 ｜架构 §4.3 合规 R11、电商法 §34
- R-02 房间须知可配置内容块（含用户侧披露）｜架构 §6、PRD §7.1.5
- R-03 词库类风控配置版本化但免公示 ⚠（H5 联动约定）

## 8. 非功能要求
- 快照查询 P95 ≤30ms（缓存现行版+版本号失效）。

## 9. AI 开发标准（本模块附加）
- TDD：公示 7 日边界、快照取版本正确性（跨版本时刻）、须知内容拉取；
- 禁止：规则未公示直接 EFFECTIVE（守卫）。
