# D2 提醒服务

> 域：D-履约 ｜ 架构模块：notify + 调度 ｜ V1 ｜ P0 ｜ 阶段：②
> 上游：C3（成团 job 预写）、C5（改期重投）、I2（job 触发） ｜ 下游：I1（推送/SMS）、D5（房间内 Agent 同步提醒）、C5（改期入口承接） ｜ 技能：P0六件套

## 1. 职责与边界
- 做：四档提醒（24h/1h/10min/1min）编排（job 事实源+延迟消息优化）；房间内 Agent 同步提醒；确认到场/申请改期入口承接。
- 不做：推送通道执行（I1）；改期流程（C5）。

## 2. 功能点
- 成团时预写四个 I2 job（due_at = scheduled_start - 24h/1h/10min/1min）
- 提醒内容：场次信息+到场确认按钮+改期入口
- 房间内同步提醒：宽限开始/结束前 1min 消息（经 D5，@Agent 名义非法律意见）

## 3. 领域模型
notification_jobs(id, ref_type, ref_id, user_id, kind varchar(16), -- REMIND_24H|REMIND_1H|REMIND_10MIN|REMIND_1MIN
  due_at timestamptz, status varchar(12), sent_at)  -- 与 I1 共表或分离由实现定

## 4. 关键流程
ScheduleJobFired(REMIND_x) → 幂等回查（场次未取消/未结束）→ I1 推送 + D5 房间消息（进行中房间）→ 标记 sent。
取消/改期/流标 → 业务侧作废未发 job（同事务）。

## 5. 接口契约
| POST | /enrollments/{id}/confirm-arrival | - | {status} | - | 幂等键=enrollment
提醒编排内部 API（消费 job 事件），无独立 HTTP。

## 6. 领域事件
- 生产：ReminderDispatched{ref, kind}（→H4 到达率相关统计辅助）。
- 消费：SessionFull/Confirmed（预写）；RescheduleConfirmed（重投）；SessionCancelled（作废）。

## 7. 业务规则
- R-01 四档自动提醒 ｜PRD §8.3
- R-02 用户可确认到场或申请改期（入口透传 C5）｜PRD §8.3
- R-03 提醒取消场景作废（job 同事务作废，避免幽灵提醒）｜架构 §4.5

## 8. 非功能要求
- 提醒准时误差 ≤15s（job 粒度）；触达率统计（I1 回执）。

## 9. AI 开发标准（本模块附加）
- TDD：四档时点、取消作废、幂等重放不重复发送；
- 禁止：提醒判断依赖延迟消息（job 是事实源）。

## 10. 验收清单
- [ ] 四档 job 准点触发（时间注入测试）
- [ ] 取消场次后无提醒发出
- [ ] 宽限结束前 1min 房间内消息可见（D5 联调）
