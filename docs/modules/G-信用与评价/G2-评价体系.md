# G2 评价体系

> 域：G-信用与评价 ｜ 架构模块：review ｜ V1 ｜ P1 ｜ 阶段：④
> 上游：D1（房间结束触发） ｜ 下游：G1（信用联动）、C1（排序因子）、H4 ｜ 技能：P0六件套

## 1. 职责与边界
- 做：房间结束后用户与律师互评（四维）；匿名机制（凭证分离+48h 延迟开放）；评分入排序因子。
- 不做：信用分计算（G1）；排序引擎（C1 消费评分）。

## 2. 功能点
- 四维评分（专业度/响应速度/服务态度/整体满意度 1-5）+ 评语（可匿名）
- 48h 延迟开放展示；匿名评价仅展示维度分+评语
- 双向互评（房间结束后 7 天窗口，过期不可评）

## 3. 领域模型
reviews(
  id bigserial PK, session_id bigint NOT NULL, direction varchar(8) NOT NULL,  -- user_to_lawyer|lawyer_to_user
  dims jsonb NOT NULL,                         -- {professional, response, attitude, overall}
  comment text NULL, anonymous boolean NOT NULL DEFAULT true,
  created_at, UNIQUE(session_id, direction)
)
review_credentials(id PK, review_id UNIQUE NOT NULL, user_id bigint NOT NULL)  -- 运营默认不可 join，纠纷调查经 H9 审批

## 4. 关键流程
RoomClosed → 48h 后开放评价入口（7 天窗口）→ 提交 → 匿名拆分存储（reviews 无 from 字段；凭证表分离）→ G1 联动（正向加分）→ 48h 后对外展示。

## 5. 接口契约
| POST | /reviews | {session_id, direction, dims, comment?, anonymous} | {review} | 409 DUP / 400 WINDOW_CLOSED | 幂等键=session+direction
| GET  | /lawyer/{id}/reviews | - | 维度均分+评语列表（匿名） | - | 否

## 6. 领域事件
- 生产：ReviewSubmitted{session_id, direction, dims}（→G1、C1、H4）。
- 消费：RoomClosed（开放计时）。

## 7. 业务规则
- R-01 房间结束后互评；四维；匿名可 ｜PRD §7.1.7
- R-02 评价影响律师信用分与排序 ｜PRD §7.1.7
- R-03 凭证分离存储；运营默认不可关联；48h 延迟开放；仅展示维度分与评语 ｜架构 §5.1 合规 R14
- R-04 残余风险标注：5-6 人小房间强匿名不可达（文档明示）｜架构 §5.1

## 8. 非功能要求
- 评价查询 P95 ≤200ms；排序因子聚合 T+1。

## 9. AI 开发标准（本模块附加）
- TDD：窗口边界（48h/7d）、匿名拆分（reviews 表无 from 断言）、重复评价幂等；
- 禁止：reviews 表出现 user_id；评价直改信用分（走 G1）。
