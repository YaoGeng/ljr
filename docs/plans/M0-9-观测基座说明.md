## 3. core OTel 装配（services/core/src/observability/）

依赖线（npm registry.npmjs.org，全部精确锁版）：`@opentelemetry/api@1.9.1` +
`sdk-node@0.223.0`（exporter-* 同 0.223.0 / sdk-trace-base、sdk-metrics 2.12.0）+
`auto-instrumentations-node@0.81.0`（只取 **http+pg 两件**——按 instrumentationName 过滤，
不注册全量插桩，控制 patch 面）。pnpm 侧新增 `onlyBuiltDependencies: [protobufjs]`
（OTLP 传递依赖，postinstall 仅生成 version 自述文件）。

三件：

- **otel.setup.ts**：`setupObservability(options)` 装配入口。
  - 端点走 OTel 标准键 `OTEL_EXPORTER_OTLP_ENDPOINT`（仅进程 env，如
    `http://127.0.0.1:4318`）——**未设且未注入 exporter 时降级为 NoopSpanProcessor**：
    provider 照常注册（trace 上下文可取）、span 不外发、零网络零内存增长，本地/单测不炸。
    注意 sdk-node 0.223 在 spanProcessors 为空数组时**不注册 provider**（已核 dist 源码），
    必须给 Noop 占位。
  - 注入 spanExporter（测试口径）→ SimpleSpanProcessor 即时可断言；OTLP 生产路径 →
    BatchSpanProcessor 攒批 + 同端点 PeriodicExportingMetricReader（15s）。
  - `enabled=false`（LJR_OBS_ENABLED，三层配置解析，默认 true）：不注册 provider、不插桩、
    日志不查上下文——进程零观测开销。
  - 重复装配防护：api 无 unregister，装配前 `trace.disable()` 复位全局位（生产单进程只装一次，
    该调用为幂等空操作；测试同进程多文件各装一次时保证独占）。
- **trace-logger.ts**：单行 JSON 日志（ts/level/svc/trace_id?/msg/…fields）。trace_id 仅在
  存在真实 active span 时注入（全零 trace_id 视为无 trace，不输出占位）；兼容 Nest
  LoggerService，main.ts 经 `bufferLogs + useLogger` 挂为全局 logger；日志永不反噬业务
  （sink 异常/字段序列化失败均兜底）。
- **observability.module.ts**：Nest 接缝（@Global）。OBSERVABILITY_OPTIONS 为注入位
  （测试 overrideProvider 注 InMemorySpanExporter / enabled:false，不真连 collector）；
  app.close() → onApplicationShutdown → sdk.shutdown()（flush 批处理器、解除插桩）。

## 4. trace 传播约定（为 M1 预定口径）

- **入站**：HTTP 入口由 HttpInstrumentation 按 W3C `traceparent` 续接上游 trace（无头则新起）；
  M1 起 App/后台的客户端调用若要贯通，须透传响应头 `traceparent`（SDK 默认注入响应头）。
- **进程内**：AsyncHooksContextManager 维持 active span；**日志行 trace_id 与当前 span 同源**
  （trace-logger 的 currentTraceId），排障时以日志 trace_id 反查 jaeger 全链路。
- **API→DB**：PgInstrumentation 为每条查询生成子 span（parent=入口请求 span），
  trace_id 贯通 API→DB；M1 起若查询语句含敏感字段（用户原文），须经 instrumentation 的
  queryHook/config 收敛 `db.statement` 记录面（脱敏红线：用户原文进 LLM 前过实时脱敏层，
  架构 §1.3——trace 属性同受约束）。
- **出口**：唯一 OTLP 端点（collector）；跨服务（rtc-im/agent-assist/payment-gateway）
  接入时沿用同一 compose 段 collector 与同一约定，不在各服务自建后端。

  trace-logger.spec（trace_id 注入/缺省/开关/异常兜底）、observability.module.spec
