## 0. 三件套原文与实现映射

技能指南 §7-5 第 5 条原文（docs/03 L205，逐字）：

> **运行时隔离（v2.0 新增）**：agent 执行环境网络出站白名单（仅包仓库与批准的 API 域）；实名/支付/凭据相关目录与密钥存储对 agent 文件系统不可见；第三方技能附带的脚本一律先在**无凭据的隔离容器**中首跑审行为；

| 原文要点 | 承载物（本记录章节） | 执行面 |
|---|---|---|
| 网络出站白名单（仅包仓库与批准的 API 域） | §1 初始清单 + `scripts/sandbox/first-run.mjs` 校验 3（EGRESS_NOT_ALLOWED） | 宿主建议 + 脚本层校验 |
| 实名/支付/凭据相关目录与密钥存储对 agent 文件系统不可见 | §2 `.secrets/` 约定 + git 三证 + gitleaks + `first-run.mjs` 校验 2（CRED_DIR/CRED_FILE，容器挂载面） | git 层 + CI 层 + 脚本层 |
| 第三方技能附带的脚本一律先在无凭据的隔离容器中首跑审行为 | §3 `first-run.mjs`（`docker run --rm --network none --read-only` + 无 env 透传 + 三重防御校验） | 脚本层（真跑待 docker 环境） |

四层防御分工（如实声明边界）：git 层（gitignore 防入库）→ CI 层（gitleaks 全历史扫描兜底）→ 脚本层（first-run 三重校验）→ 宿主层（agent 权限模式，**由用户控制，仓库侧只能建议+记录**，见 §1.3）。

### 1.3 宿主权限模式建议（用户控制项，仓库侧仅建议+记录）

- **建议** agent 宿主（ZCode 等）以受限权限模式运行：网络类命令（curl/wget 等）与仓库外文件访问默认**询问后放行**而非自动批准；会话工作目录圈定仓库根；不授予 `.secrets/`、`~/.ssh`、`~/.aws` 等凭据路径的读取权限。
- 仓库侧已落地的执行面（不依赖宿主配合）：`first-run.mjs` 三重校验（脚本层）+ CI gitleaks（入库层）+ gitignore（git 层）。宿主层是第四段，由用户按所用 agent 的权限配置自行收紧。

### 1.4 白名单扩展流程

1. 临时放行（单次审计）：`first-run.mjs --allow-domain <host>`——输出行留痕（「本次扩展：<host>」），不改清单；
2. 永久新增：给理由记入本表 §1.1 → 同步 `DEFAULT_EGRESS_ALLOWLIST` → 过测试断言 → 提交说明理由。批准的 API 域（如后续 LLM 供应商）按此流程逐个入册。

## 2. 凭据目录不可见（.secrets/ 约定 + gitleaks 覆盖）

### 2.1 约定

- 真实凭据只存 `.secrets/`（**已 gitignore**，.gitignore L11），按环境分文件（dev.env 等；staging/prod 不落本机，走部署平台 secrets）；目录内 README 为本机说明（同样不入库）。
- 注入方式 = **env 文件 + 进程环境**（`docker --env-file` / `node --env-file` / 平台 secrets 注入进程环境变量），**一律不经命令行参数**——argv 对同机进程可见（ps 泄露面）。约定样张=根 `.env.example`（占位值 FAKE-TOKEN-FOR-DRILL）。
- 容器/沙箱面：`first-run.mjs` 拒绝任何含凭据目录/凭据名文件（`.secrets/`、`.ssh/`、`.env*`、`*.pem`、`id_rsa` 等，全清单见脚本 CRED_DIRS/CRED_FILES/CRED_FILE_PATTERNS）的挂载源——挂进容器即对 agent 可见（演练 C-4）。

### 2.2 演练：伪造 .secrets/ 文件 → git 不可见三证

伪造凭据落盘（占位值）：`.secrets/dev.env`（内容 `LJR_LLM_API_KEY=FAKE-TOKEN-FOR-DRILL`）+ `.secrets/README.md`。

```
$ git check-ignore -v .secrets/dev.env .secrets/README.md
.gitignore:11:.secrets/	.secrets/dev.env
.gitignore:11:.secrets/	.secrets/README.md

$ git add --dry-run .secrets/dev.env        # 不真暂存
The following paths are ignored by one of your .gitignore files:
.secrets
hint: Use -f if you really want to add them.

$ git status --porcelain                     # 无任何 .secrets 条目（仅本次施工改动）
 M .gitignore / M .gitleaks.toml / M .prettierignore
?? .env.example / ?? scripts/sandbox/
```

三证：check-ignore 命中规则行；`git add` 默认拒绝（-f 才能强加）；status 不可见。

### 2.3 gitleaks 覆盖确认（本机真跑，版本与 CI 镜像同 tag）

本机取得 gitleaks **v8.24.3** Windows 二进制（GitHub Releases 官方资产，与 CI 镜像 `zricethezav/gitleaks:v8.24.3` 同版本；下载存于 gitignored 沙箱），用仓库 `.gitleaks.toml` 实跑四项：

| # | 演练 | 结果 |
|---|---|---|
| 1 | 主仓库全历史扫描（与 CI job 同命令：`detect --source . --config .gitleaks.toml --redact --verbose --exit-code 1`） | **17 commits scanned, no leaks found, exit 0** |
| 2 | 种子检测验证（临时 git 仓库植入真实样态合成密钥：`AKIA`+16 位合成大写串、`ghp_`+36 位合成串） | **2 条规则命中（aws-access-token / generic-api-key），exit 1**——证明工具+配置真能抓，不是空转 |
| 3 | `.env.example` 豁免核对（no-git 工作区扫描，711MB 全量） | 217 处命中**全部**位于 gitignored 本地工具目录（.tools 176 / .mimosa 40 / .superpowers 1），**新增文件 0 命中**——豁免项工作正常且未误伤 |
| 4 | 配置行为核对 | CI 用法 `detect` 依 git 全历史：`.secrets/` 因 gitignore 永不入历史 → 无扫描面；`.secrets/` 不在任何豁免项；本次将 `.env.example` 豁免从 docker/dev 单点泛化为 `(^|/)\.env\.example$`（示例文件=占位值申报处，docker/dev 与根两处同规则） |

附带发现（如实记录）：AWS 官方文档示例值 `AKIAIOSFODNN7EXAMPLE` 被 gitleaks 默认规则 stopwords 抑制（对文档样例值的降噪设计）——故种子检测验证改用无 stopword 子串的合成值；同时提示**文档示例形态的密钥不必然被默认规则捕获**，依赖 gitleaks 之外的三层防御。

## 3. 第三方脚本首跑容器包装（first-run.mjs）

`scripts/sandbox/first-run.mjs`：审计（三重防御校验）→ 全过则生成最小权限 docker 命令；任一 BLOCKER 即拒绝、不生成命令。隔离参数：`--rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534:65534 --tmpfs /tmp:rw,noexec,size=64m` + 唯一挂载 `<脚本所在目录>:/sandbox:ro` + 唯一显式 env `HOME=/tmp`（字面量，宿主环境变量一律不透传=无凭据环境）。防御校验：路径穿越（PATH_ESCAPE）/ 凭据目录（CRED_DIR/CRED_FILE）/ 出站白名单（EGRESS_NOT_ALLOWED），另含不支持类型、镜像未锁 tag、超扫描上限（SCAN_INCOMPLETE，审不动就拒绝）。已知边界见脚本头注。

### 3.1 演练 C-1：干净脚本 dry-run（通过，输出将执行的 docker 命令）

```
$ node scripts/sandbox/first-run.mjs --dry-run <acceptance>/t6/fixture-clean/postinstall-check.mjs
[first-run] 审计目标：...fixture-clean/postinstall-check.mjs（runner=node）
[first-run] 挂载源：C:\...\t6\fixture-clean → /sandbox（只读）
[first-run] 出站白名单：registry.npmjs.org, github.com, api.github.com, registry-1.docker.io, auth.docker.io, production.cloudflare.docker.com
[first-run] 扫描：2 个路径 / 1 个文本文件 / 354 字节 / 1 处 URL 引用
[first-run] 审计通过，将执行（dry-run 输出，未真跑）：
MSYS_NO_PATHCONV=1 docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534:65534 --tmpfs /tmp:rw,noexec,size=64m -e HOME=/tmp -v "C:/Users/yg/Desktop/ljr/.superpowers/sdd/M0-工程基建执行计划/acceptance/t6/fixture-clean:/sandbox:ro" --workdir /sandbox node:24-alpine node postinstall-check.mjs
```

### 3.2 演练 C-2/C-3/C-4：三条拒绝路径（各 exit 1）

```

  [EGRESS_NOT_ALLOWED] 白名单外域名引用 evil.example.com（phone-home.mjs:2）——临时放行走 --allow-domain evil.example.com 并留痕；永久新增须记入演练记录 §1 并给理由

C-3 路径穿越（脚本在受控根外：C:\Users\yg\AppData\Local\Temp\ljr-t6-outside\escape.mjs）：
  [PATH_ESCAPE] 目标脚本越出 --root（C:\Users\yg\Desktop\ljr）：...escape.mjs（首跑审计对象必须落在受控根内）

C-4 挂载源含凭据目录（干净 setup.sh 同目录带 .secrets/dev.env）：
  [CRED_DIR] 挂载源含凭据目录：.secrets（挂进容器即对 agent 可见，违反 §7-5 第 5 条）
```

拒绝时不输出 docker 命令（不给「照抄绕过审计」的原料）。

### 3.3 自测与真跑补演练标注

- 自测：`bun test scripts/sandbox/` → **22 pass / 0 fail**（四类用例：最小权限命令面——无网络/只读挂载/无 env 泄露/权限收敛；出站白名单不漏报不误报+清单成员集锁定；凭据目录拒绝；路径/类型防御+CLI 子进程回归——真跑 --dry-run 与三条拒绝路径的 exit code 断言）。
- **待补真跑**：本机无 docker（Ruling-6），容器首跑=「脚本交付+逻辑自证（上述 dry-run 输出）」；docker 环境就位后去掉 `--dry-run` 直接真跑（脚本已实现 spawn docker 并置 `MSYS_NO_PATHCONV=1` 防 Git Bash 路径改写），补记容器内行为观察（预期：网络访问全部失败、挂载只读、tmpfs 可写不可执行）。

## 4. agent-scan 补装尝试（M0-6 遗留）

尝试过程（2026-10-13，如实记录）：

1. 上游可达性：`github.com` 网页直连超时（000），但 `api.github.com` 可达（200）——改走 GitHub API 核实；
2. 仓库元数据（api.github.com/repos/snyk/agent-scan）：**3,135 star**（docs/03 §2 表记 3,132，微涨符合时间推移）、**Apache-2.0**、default_branch=main、pushed_at=**2026-10-09**（活跃）、未归档；
3. 全库树核实（git/trees API，recursive，524 文件，未截断）：**仓库根无 SKILL.md**——`tests/skills/*`（algorithmic-art、canvas-design、malicious-skill 等）是其测试夹具，不是可装载技能；源码形态=Python 包（`src/agent_scan/`）；
4. README 全文（API contents 端点取回）：官方声明**不发 npm 包**；安装=**`uvx snyk-agent-scan@<version>`** 或 GitHub Releases 独立二进制；运行前置=**注册 Snyk 账号取 API token（SNYK_TOKEN）**；CLI 输出 experimental（v0.5.x 与 v0.6+ 输出结构均声明会变）；
5. 本机不可跑的硬原因：本机 Python 为 WindowsApps 占位 stub（AGENTS.md Ruling）、无 uv、无 Snyk 账号 token、`api.snyk.com` 出站实测 000（§1.2）。

**结论：上游存在且活跃，但形态是「云分析 API 支撑的 Python CLI 工具」，不是技能包——不可按技能 vendor 入 `skills/`（vendor 语义=SKILL.md 快照固定，对工具无意义）；且本机运行四前置全缺。**处置：`skills/manifest.json` pending 项已更新为上述核实后事实（status=「待引入（上游已核实：工具型 CLI，非技能包）」，含引入路径=uvx 本地或 CI 容器化）；装前扫描以**人工审读替代**（M0-6 已对 18 个 vendor 文件执行：全量 grep 无 curl/wget/eval/出站调用/密钥样态，唯一可执行脚本 find-polluter.sh 审读为纯本地操作）。引入条件齐备时按技能指南 §7-1/§7-2（扫描+人工审读）与 §7-7（更新视同新装）执行并回写 manifest。
