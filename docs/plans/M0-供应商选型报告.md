## 1. LLM 供应商（D11）

### 1.1 用途与约束（来自 E1 / 架构 §1.3-5、§4.6）

- 用途：E1 草稿气泡管线的 LLM 草稿生成段（预算 ≤4s，全管线 P95 ≤8s）。输入是**脱敏后**文本（NER+规则把姓名/证件/电话/地址替换为占位符），输出仅推律师端气泡、经律师审查。
- 硬约束：境内运营、数据不出境、输入不留存且不用于供应商训练、采购前签署 DPA/委托处理协议；切换供应商需重过合规检查。禁止境外 LLM SDK 引入（E1 §10 禁止项）。

### 1.3 推荐：智谱 GLM（主）

理由：
1. **DPA 达成概率最高**：标准协议已有「未授权不使用」条款 + 2026-09 新上线的「数据内容不留存」机制 + 企业版书面「数据默认不用于模型训练」承诺——三条线索都指向智谱对 B 端数据隔离有成熟产品化能力，把红线条款（不留存、不训练、禁匿名化再利用）写进 DPA 的谈判基础最好。
2. **联调成本最低**：免费 Flash 模型（GLM-4.7-Flash 等）可直接充当联调期真模型，比纯 mock 更早暴露格式/延迟问题，且不花钱、不涉及真实用户数据（联调数据本身也过脱敏层）。
3. 价格中档（GLM-5.3-Flash 0.8/2.8 元/百万 tokens），草稿生成段预算 ≤4s 可满足。
4. 风险点明确可控：标准用户协议的「匿名化数据可训练」条款必须**在 DPA 中显式排除**，未签 DPA 前不接真实流量（红线不破）。

### 1.4 备选

- **通义千问（阿里云百炼）**：官方 FAQ 白纸黑字「API 数据不用于模型训练」，价格最低档之一（qwen-flash 输入 0.15 元/百万），100 万 Token 免费额度；若智谱 DPA 谈判受阻，切换成本低（E1 管线以适配器隔离，切换不改主流程）。留存条款（监管要求存储）需在 DPA 中约定删除期限。
- **DeepSeek**：价格最优（闲时 flash 输入 1 元/百万），但协议对训练用途与留存**双空白**，DPA 需从零谈，仅作成本备胎。
- **不推荐首选**：Kimi（协议明文授予「输入输出用于模型服务优化」使用权，红线冲突最直接）；豆包（数据条款未能核实，暂不入围，待补核后可复议）。

## 2. 实名核验通道（D12）

### 2.1 用途与约束（来自 A2 / 架构 §5.2）

- 用途：A2 实名提交与核验（支付前实名闸口 R-01）。存储设计：**默认仅存核验结果 + 凭据摘要**，姓名/证件号密文仅在已声明目的（纠纷处理）下经审批+双人复核临时解密。
- 通道适配器 `verify_provider`（CTID|CARRIER3）已进 DDL，架构默认=适配器模式 + 沙箱 mock，prod 前替换。
- 术语澄清（对任务简报的勘误）：**CTID** 是公安部第一研究所建设的「居民身份证网上功能凭证」平台（北京中盾安信运营）；**eID** 是公安部**第三**研究所的「公民网络电子身份标识」体系——两者是不同研究所的不同体系；2025-07-15 施行的《国家网络身份认证公共服务管理办法》所定义的「网号/网证」公共服务是当前官方主推形态（[管理办法](https://www.cac.gov.cn/2025-05/23/c_1749711107835487.htm)）。

### 2.2 候选对比

| 维度 | ① CTID / 国家网络身份认证公共服务（网号/网证） | ② 运营商三要素（云市场 API，以腾讯云人脸核身为样本） | ③ eID（公安部三所体系） |
|---|---|---|---|
| 形态 | 用户侧拉起「国家网络身份认证 App」完成认证，平台**只拿到核验通过与否的结果**（不获取姓名/证件号/人脸）（[接入 FAQ](https://www.secrss.com/articles/79057)；[微信小程序接入指引](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/cityservice/ncidas/guide.html)） | 云 API：校验「手机号+姓名+身份证号」一致性（[接口文档](https://cloud.tencent.com/document/product/1007/39765)），平台需上传明文三要素给通道方 | 经三所资格审查的 eID 网络服务机构（金联汇通等）代理接入（[证券时报](https://www.stcn.com/article/detail/541919.html)） |

| 接入周期 | **待核实**（官方路径=通过国家网络身份认证 App 人工客服联系，未见公开 SLA；接入资质门槛未见公开文件） | 最短：企业实名云账号 → 控制台开通人脸核身产品 → API 密钥即用；按量后付费 | 长（需经代理机构签约） |
| 沙箱/试用 | 无沙箱概念（认证即真实）；可用自有证件做少量真实调用验证 | 新用户有免费试用申请入口（[产品页](https://cloud.tencent.com/product/faceid)；**额度数待核实**）；mock 适配器+测试号牌可完全本地联调 | 待核实 |

### 2.3 推荐：运营商三要素（主通道），CTID/网证作为 V2 演进

理由：
1. **周期与沙箱**满足 D12 默认策略（适配器 + 沙箱 mock，prod 前替换）：云 API 当天可通，mock 适配器先行不阻塞 A2 施工。
2. **价格可算**：实名是一次性动作（支付前闸口），按 1.1-1.2 元/次预算即可；对比 CTID 的零价格，合规上我们本就只存结果+摘要（A2 DDL 设计），三要素通道下明文只在核验瞬时经过通道方，配合 DPA 与 PIA 登记可控。
3. CTID/网证是监管明确方向（PIPL 最小化最优解），但**接入资质、周期、收费全部未公开**——V1 不押注，V2 再迁移（`verify_provider` 适配器已预留 CTID 枚举值）。
4. eID（公安三所）：路径重、信息少，V1 排除。

### 2.4 备选

- CTID/国家网络身份认证：建议**现在就启动咨询**（见附录 A-3，须用户本人联系），把周期/资质摸清，为 V2 或监管加码留通路。
- 阿里云市场同类三要素 API（多家服务商）可在腾讯云议价时作为比价筹码（价格区间 **待核实**，未取到官方页）。

## 3. RTC 厂商（声网 Agora vs 腾讯云 TRTC）

### 3.1 需求（来自 D1/D5/D6 / 架构 §2.3）

- 房间音视频：拼单房间（多人）+ 1对1 房间（双人）；**单人进入等待态**（宽限期 5 分钟内用户先进房）→ 单人频道支持是必备（两家均为标准能力，非差异项）。
- 云端录制：**仅 1对1 录制**（双方 recording_consent 信令齐才启动，D5 R-03）；拼单房间默认不录制（D10 默认）。录制文件落 OSS 合规 bucket（WORM）+ 哈希上链。→ 需要按需启动/停止的云端录制 API（两家均支持按任务启停）。
- SDK 形态：App=Expo/RN（双端 iOS/Android）。R11 提醒：M3-W1 前未就绪则**文本房间先行**（D5 自研 WSS 文本是 M2 基线，RTC 只承担音视频+录制，非阻塞依赖）。
- 合规：厂商列入供应商准入合规清单（数据驻留、留存策略；录制内容属于 1对1 会话录音，留存 ≥3 年由我方 OSS 承担，厂商侧录制仅中转）。

### 4.3 推荐：微信平台收付通（主）+ 支付宝直付通（备）

理由：
1. 架构 §2.3 既定基线（微信主+支付宝备），本次调研未发现推翻依据；分账/合单/多次分账/回退能力与 F3 设计（唯一解冻分账节点、HOLD、违约扣减）逐项对得上。
2. 律所进件 API 与 A3b 状态机（SUBMITTING→IN_REVIEW→ACTIVE）直接映射微信「申请单→审核→账户验证→签约」流程。

### 4.4 风险与顾虑（须用户/商务确认）

- **R-A（关键路径）：ICP/EDI 许可证前置**。平台收付通开通需要与商户号主体一致的 ICP 许可证或 EDI 许可证，而证照办理本身有行政周期（**办理周期待核实**，与 D15/M5 prod 门禁联动）——支付通道的真实排期瓶颈不在微信审核（1-3 工作日）而在证照。建议 M0-M1 期间就把证照申请排上（须用户本人办理）。
- **R-B：分账比例上限**。默认上限 30%；F3 构成中「缺席分成 30% → 平台」已占满上限，若未来平台服务费（fee_versions 规划 0% → 5-10%）与缺席分成同笔叠加，平台侧分账比例将 >30%——需与微信商务确认：a) 提高分账比例的白名单申请，或 b) 业务上限定「服务费仅在无缺席分成场次计提」。**此点涉及 F3 计算口径，拍板前须澄清**。
- **R-C：无完整沙箱**。联调只能走仿真测试系统+小额真实交易；F1 通道模拟器（R1 应对）+ 沙箱限定 R-05（仅测试商户号可封装 agent 工具）必须先行落地。
- **R-D：付呗等其他聚合支付**：定位偏线下商户聚合收款，无电商二级商户分账 API 生态与本项目形态匹配（**待核实**，未深入调研，暂不入围）。
