## 1. 背景：为什么全程 AI 开发需要 Skills

本项目的**代码产线**没有传统工程师把关（人工门禁如 PIA/证照审核、律师资质审核仍在，见架构 §6/§7.1）。代码由 AI coding agent（Claude Code / Codex / Cursor / omo 等）产出，agent 的工作纪律就是产线的质量地基。

Skill（技能）是 agent 的可加载操作手册——一个含 `SKILL.md` 的文件夹（遵循 agentskills.io 标准），agent 加载后会在对应任务上自动采用专家流程，而不是每次靠临时发挥。全程 AI 开发时，正确选型 skills 等于给 agent 配备：

1. **工程纪律**（先写测试、假设驱动调试、完成前验证）——弥补产线无人 Review 的质量缺口；
2. **领域专长**（前端设计、数据库安全查询、Playwright 测试）——弥补资深经验缺口；
3. **项目规则内化**（自建 skill，见 §6）——把架构文档的硬约束变成 agent 每次写代码前的自动检查。

### 1.1 选型标准（v2.0：安全前置）

收录顺序固定为（前一条不通过即淘汰，不看 star）：

| 顺位 | 标准 | 说明 |
|---|---|---|
| ① | **内容审读与来源可信** | 审读 SKILL.md 与其引用脚本（警惕 curl/eval/外传数据段）；来源限于官方/已核实仓库/两大索引清单 |
| ② | **许可证** | MIT/Apache-2.0 可放心；GPL 仅按 §7.5 处理；**许可证无法确认的一律按不可商用处理**（不得修改后分发、不得把技能内容分发进产品）；仅内部加载参考须显式标注（如 anthropics/skills，见 §2 注） |
| ③ | **维护活跃度** | 近 90 天有 push；上游停更超 6 个月触发退役评估（§9） |
| ④ | **star（同分决胜）** | 社区热度仅在①-③通过后作排序参考 |

另三条收录规则：
- **agent 兼容性**：收录时须声明该 skill 在本项目选用的各 agent 下已验证可装载、可触发（omo / Claude Code 至少各验一个）；
- **技能冲突裁决**：同触发域同名/同职责技能只保留一个，弃用者记录在案（现裁决见 §4.2）；
- **上下文预算**：同时装载上限建议 ≤15 个；超出按 §9.2 分阶段批次装载，任务结束后停用不常用批次。

## 4. 按项目域的技能映射矩阵

映射基准：`docs/02-架构设计.md` 的域划分与技术选型（§2.3、§3.2）。

**已确认不适用**：i18n（V1 单城市中文，PRD/架构均无国际化需求）、无障碍（两份输入文档均未要求）——避免误读为遗漏。

### 4.1 工程纪律与支付不变量（所有开发，P0）

**装**：superpowers P0 六件套（TDD、systematic-debugging、verification-before-completion、writing-plans、requesting-code-review、receiving-code-review）+ **自建 `lj-payment-invariants`**（§6，与 TDD 并列为支付域第一闸）。

**用法要点**：本项目资金/状态机代码密集（架构 §4.1-§4.4）——每个状态迁移守卫先写失败测试；支付回调、成团守卫必须跑过测试才能报完成；支付/结算代码改动前 `lj-payment-invariants` 自动加载（幂等号唯一、Inbox 双唯一、分账唯一触发节点、HOLD、对账 SLA）。

### 4.2 架构与领域设计（§2-§4，P1）

- **NeoLabHQ/context-engineering-kit**（1,755 star，GPL-3.0）：software-architecture 技能（Clean Architecture/SOLID）与本项目模块化单体 + 模块边界强制（架构 §2.1）对口。**按 §7.5 处理，不直接装载**。
- **superpowers**: brainstorming（架构 §10 待澄清决策点收敛）、writing-plans（架构文档转施工计划）。
- **冲突裁决**：NeoLabHQ 亦含 subagent-driven-development，**只保留 superpowers 版本**（MIT、star 高一个量级），NeoLabHQ 同名技能不装——记录在案。

### 4.3 后端与数据库（Core API / PostgreSQL / RocketMQ / Redis，§2.3、§4.2、§5，P1）

- **sanjay3290/ai-skills**（432 star，Apache-2.0）：`postgres`——只读安全 SQL（多连接、纵深防御），匹配 §7.2 资损不变量巡检的数据排查；同仓库 `mssql/mysql` 按需。**注：RocketMQ/Redis 专项技能经检索未达收录标准，列入待核实（附录），当前由 superpowers TDD + 架构文档规则承载。**

### 4.4 前端与移动端（RN App 双角色 + React Web 后台，§2.3，P0/P1）

## 6. 自建技能：把项目规则内化（最高价值）

外部 skill 解决通用工程能力；**本项目的壁垒规则（资金合规、状态机守卫、履约罚则）没有现成 skill，自建才是差异化**。用 [anthropics/skills 的 skill-creator](https://github.com/anthropics/skills/tree/main/skills/skill-creator) 生成，放进仓库 `skills/` 目录随代码版本化：

| 自建 skill | 内容（喂给它什么） | 触发时机 |
|---|---|---|
| `lj-domain-rules` | 交易状态机守卫（架构 §4.1：B2C/C2B/改期/**1对1订单/账号注销/律所进件**全部状态机）、时间段锁规则（§4.2：模板物化、部分唯一索引、同事务释放）、价格快照（§4.3：NUMERIC 物化、禁 float） | agent 写 trade/schedule/pricing/fulfillment/identity 模块代码前自动加载 |
| `lj-compliance-guards` | 资金不过平台账户四条红线（§1.3）、留存 3 年（§5.2）、单独同意（§5.2）、AI 不出庭（§4.6）、LLM 供应商硬约束（§1.3-5） | agent 改 payment/settlement/agent-assist 代码时自动加载 |
| `lj-payment-invariants` | **支付工程不变量（v2.0 新增）**：Inbox 双唯一约束、`payment_orders.idempotency_key` 唯一、成团原子守卫 SQL 模式（§4.4）、分账唯一解冻节点、结算 HOLD、T+1 对账差异工单 SLA 24h、支付回调报文守卫要点 | agent 改 payment/settlement/支付网关代码时自动加载 |
| `lj-data-security` | **数据安全编码规则（v2.0 新增）**：列加密+HMAC 盲索引、实时脱敏层接入点（§4.6）、分级导出、到期处置作业（§5.2） | agent 改 identity/agent-assist/存储层代码时自动加载 |
| `lj-test-matrix` | PRD §8.2 改价矩阵、§8.7 取消矩阵、§8.8 信用全表转成的组合测试清单 | agent 写履约/信用/支付测试时自动加载 |

**文档→skill 同步机制**：架构文档 §4/§5 的任何修订，其 PR 模板内含"skill 同步检查单"（受影响的自建 skill 清单）；skill 变更与文档变更**同 PR 合入**，禁止分批。

## 7. 安全与许可证（装第三方技能前必读）

第三方 skill 是**供应链风险**（提示注入、脚本执行、数据外泄），本项目涉及实名/支付/法律咨询数据，纪律编号如下：

1. **来源初筛**：只装 §2 已核实仓库；新发现技能先查 star、近期 push、issue 健康度；
2. **装前扫描**：snyk/agent-scan 扫描 + 人工审读 `SKILL.md` 与引用脚本；
3. **版本固定**：vendor 到仓库 `skills/`，固定 commit；
4. **权限最小化**：技能不给生产凭据、支付密钥、KMS 权限；密钥走 secrets 管理，不进 skill 内容；生产支付通道永不封装为 agent 可调用工具（与 §4.3 互引）；
5. **运行时隔离（v2.0 新增）**：agent 执行环境网络出站白名单（仅包仓库与批准的 API 域）；实名/支付/凭据相关目录与密钥存储对 agent 文件系统不可见；第三方技能附带的脚本一律先在**无凭据的隔离容器**中首跑审行为；
6. **事件响应（v2.0 新增）**：发现恶意/疑似恶意 skill 的处置程序——全环境撤销清单（所有 agent 目录 + 仓库 vendor 目录）、受影响凭据轮换、已执行任务审计回溯；
7. **更新视同新装（v2.0 新增）**：第三方技能任何更新重新走扫描 + 审读，不接受"只看 diff"。

许可证细则：
- MIT/Apache-2.0 可放心装载；
- **anthropics/skills 许可证未声明（API license=null）**：按"仅内部加载参考、不随产品分发、不修改后分发"处理；若需把技能产出的模板/代码分发进产品，需权利方确认；
- **GPL-3.0（NeoLabHQ）**：不分发其内容、不逐段改写；DDD/Clean Architecture 为公开通用方法论，按架构文档口径自行编写的 skill 不构成演绎作品；如确需参考原文，走法务确认。

## 8. 安装与验证（v2.0 重写）

### 8.1 唯一事实源与分发机制

**仓库 `skills/` 目录 = 技能唯一事实源**（vendor 固定 commit + 自建技能同仓版本化）。各 agent 从这里分发，禁止直接往用户目录拷贝未入库技能：

| Agent | 分发方式 |
|---|---|
| **omo** | 配置/环境变量 `OMO_SKILLS_DIR` 指向仓库 `skills/`（或启动任务从仓库同步至 `$OMO_SKILLS_DIR`，默认 `~/.omo/agent/skills`，Windows 下 `%USERPROFILE%\.omo\agent\skills`） |
| **Claude Code** | 项目级 `.claude/skills/` 软链/同步至仓库 `skills/`；superpowers 等市场插件装后仍将版本记录回仓库 `skills/manifest.json` |
| **Codex / Cursor** | 各自 skills/agents 目录同步脚本（CI 任务从仓库 `skills/` 单向同步） |

### 8.2 两级验证（注册 ≠ 触发）

- **注册检查**：装完让 agent 列出可用技能，只证明装载成功；
- **触发验收（每个 P0 技能配固定验收任务 + 可观察判据）**：

| P0 技能 | 验收任务 | 通过判据（可观察行为签名） |
|---|---|---|
| systematic-debugging | 给一个埋了两个候选根因的 bug | agent **先产出假设清单并逐一证伪后**才改代码 |
| verification-before-completion | 任一功能任务 | 完成声明中含测试/构建**执行证据**（命令与输出），非"应该能跑" |
| test-driven-development | 新功能 | 先出现失败测试的提交，后有实现 |
| frontend-design | 生成一个页面 | 产出含设计决策说明并通过截图自检 |
| webapp-testing | 写一条 E2E | Playwright 脚本 + 运行结果输出 |

验收不过 = 检查该 skill 的 description 触发词与任务措辞匹配，或重装；连续不过即降级人工介入排查。验收记录写入 §9.3 效果日志首条。

## 9. 维护政策（v2.0 新增）

### 9.1 数据复核与变更管理

- star/活跃度/许可证**每季度复核一次**（责任人：技能管理员角色，记录于本文档 §2 表尾）；数据腐化即触发重排；
- 技能增删/版本变更记入仓库 `skills/CHANGELOG.md`，与代码 PR 同流程。

### 9.2 分阶段装载（按架构施工顺序）

| 施工阶段（架构 §13.1） | 该阶段装载批次 |
|---|---|
| ① 交易主链路（trade/payment/settlement） | P0 六件套 + 自建三件 + agent-scan |
| ② 调度/履约（schedule/fulfillment/信用） | + executing-plans、postgres、lj-test-matrix 相关组合用例 |
| ③ 前端三端（App/运营后台） | + frontend-design、webapp-testing、playwright-skill、ios-simulator（Android 待核实） |
| ④ Agent 管线与运营（agent-assist/ops） | + skill-creator、writing-skills、docx/xlsx、mcp-builder（沙箱限定） |

同时装载 ≤15 个（§1.1 上下文预算），阶段结束停用不常用批次。

### 9.3 效果反馈与退役

- 每个自建技能目录维护 `effectiveness-log.md`：agent 完成任务后标注该 skill 正/负效果（触发是否及时、规则是否被引用、是否误触发）；
- **退役标准**（满足其一）：连续 4 周零触发且任务域仍活跃、触发后产生负效果且修复两次未果、上游停更超 6 个月且无 fork 接管；
- 退役动作：从仓库 `skills/` 移除 + CHANGELOG 记录 + 各 agent 目录同步清理。
